# Audit 2026-11-25, second report: the architecture

Read at b6da352a: every stage at the level of its files' heads and contracts, the theory (wap/extensions/theory) and
its plan (notes/coc-plan.md on branch elaborator-replaces, sections 5 and 11), the build and test scripts, and what
landed on 2026-11-25. The two typers and the plan's steps R0 to R7e are known; this report says where the plan is
wrong and spends the rest on the other stages.

## Target architecture

wap built today, with what is known, has three representations and one environment.

- **Notation** (Node) is the program as written. The reader makes it and knows no word. Operators, the shape rules,
  lowering and `format` read it. Its facts are about the text only: position, file, comment, annotations, the
  spelling written.
- **The environment** is one persistent value per module: every declaration the module makes, in order, each with an
  id. That covers operator rows and aliases, raw and phrase words, rules, records and signatures, the theory's
  definitions with the bodies that unfold, layouts and primitives.
  - A module is read, shaped and elaborated inside the environments of the modules it uses.
  - A declaration accepted returns a larger environment; a refusal leaves it as it was.
  - Names resolve to declarations, never to their text.
  - A compiled module carries its environment in its wap section, so the library, a used `.wasm`, the compiler's
    warm start and the seed are one format.
- **Terms.** One elaborator, the theory's, reads one lowered statement at a time with the environment and the type it
  is wanted at.
  - It finds names, overloads, a literal's type, conversions and instances.
  - It fires the rules whose holes ask a declaration or a type.
  - It reads `enum`, `class` and `trait` as inductive declarations, and compiles match, recursion and statements.
  - The kernel accepts or refuses each term. Check, verify, run and compile differ only in what follows one
    elaboration.
- **Run terms**, a typed enum, are what erase keeps. Lowering turns them into code the emitter writes down directly:
  - closures converted, cases as decision trees, calls in last place as jumps;
  - every value in a local of a known wasm type, its layout read from the build's table of rows.

  The emitter has one case per lowered form and reasons about no type; wasm.wap encodes.
- **The runtime** (lists, texts, maps, equality, printing) is wap in the types module, over primitives, for every
  build. A build (wasm GC, or the memory one for native programs) is a table of layout rows plus the two files that
  hold a list's items and a text's bytes, chosen by an option.

The pipeline: read → operators → shape rules → lower one statement → elaborate → check (into the environment) → erase
→ lower → emit → encode.

Today's tree against it:
- In place: the reader, the operator table, the shape rules, lowering, the theory's kernel and elaborator, and
  wasm.wap.
- The environment is spread over seven mechanisms:
  - Language (23 fields);
  - Module and Signature;
  - Declarations;
  - the warm state;
  - types.wasm with its wap section;
  - the packed format;
  - the theory's Environment, inside its Theory record.
- The typer core/analyze runs beside the elaborator; the plan's switch removes it.
- The emitter decides layouts, closures and matching, does part of the typing again, and holds a runtime of its own.

## Rewrites

Ranked by what they buy. R1 and R2 are the two ends of the plan's switch, which the plan bridges where it should
rebuild them. R3 states the switch's seam right. R4 is about the gates.

### R1. One environment per module, carried by the compiled module

**Now.**
- Language (core/language.wap, 23 fields, a parameter of 192 functions in 19 files) mixes four things:
  - the language itself;
  - tables kept per file: aliases_of, reading, unparsed, standard, use_free_modules;
  - caches of one compile: operated, lowered, modules, defined_words;
  - the build: readers, memory.
- Several declarations are global to a compile: operators, precedence groups, circumfix glyphs, phrase words and
  rules. A file sees those of every file read before it, used or not, so what a file means depends on the order the
  files are read (DEBT core/rules/stages.wap:134).
- Building the environment one file is read with takes:
  - three scans of its text: its `use` lines; its raw words, split out of every line, comments included; the full
    read;
  - four walks of its tree before its operators are read;
  - working out its uses four times.

  Phrase words arrive only after the file was operated (core/pipeline.wap:115-116), so the promise at
  core/pipeline.wap:35, "each file read with the rules of the files before it loaded", does not hold.
- A rule's template binds its names where it fires (DEBT sugar/conditions.wap:44). The typer compares types by the
  text of their names and keys instances by text, so two classes of one name in two modules are one type to it; a
  name has 19 lookup paths.
- The library is held four ways, and nothing checks at load that they agree:
  - compiled, as types.wasm;
  - as source text in that module's wap section, read back by the reader (extensions/wasm/modules.wap:44-50,
    131-138);
  - operated, in the warm state (extensions/warm.wap);
  - lowered, in the warm state.

  The 219 rules and 21 patterns are compiled again on every compile.
- The theory has its own Environment: three maps changed in place, inside a Theory of 21 more fields
  (extensions/theory/elaborate/read.wap:64-104).
  - It is copied whole so that a refused statement can be taken back (read.wap:106-134); the census copies it for
    every statement.
  - Each run of a door checks the whole prelude again (elaborate/file.wap:78-89).

**Target.** `Environment` is a persistent value of declarations by id, indexed by name, by rule head and by operator
spelling; each declaration knows its module.
- A module's environment is what the types module and its used modules export, then its own declarations in order.
- A file is read, operated and shaped by its own environment alone, so a module's rules and operators reach exactly
  the files that use it.
- A template's free words are resolved when its rule is declared, in the rule's module: hygiene.
- Declaring returns a new environment or a refusal, so nothing is copied or taken back.
- Compiling a module writes its environment into the module's wap section. The front's declarations go in the packed
  format. The theory's go in its export format, which extensions/theory/export.wap writes and second/read.wap reads.
- Using a module, the library or a warm start reads that section.

**Deletes and adds** (rough), counting nothing the switch deletes anyway:
- deletes about 400:
  - Language's per-file and per-compile tables, the pre-reads, and the restart after standard_brought: about 150;
  - warm.wap: 88;
  - library.wap and the source rebuilding in modules.wap: about 110;
  - the theory's copies and roll-backs: about 60.
- adds about 280: the environment, about 200; writing and reading the section with packed.wap, about 80.
- Net about −120.

What it buys is not lines: meaning that no longer depends on read order, names that are declarations, and a compile
that reads no library source.

**Unblocks.**
- Module scoping (notes/backbone.md "Open, not built yet"), and rules that belong to their module.
- The compiled library of notes/compile_inputs.md, with one correction (What the plan misses, 4).
- The plan's R6 (one door, nothing copied), for the theory and the front alike.
- One build step fewer: the warm state is the types module's compiled section.

**Migration**, each step building itself:
1. Split Language into the frozen language of the types module and an Environment record per module, which takes
   over the per-file tables. Behavior unchanged.
2. Scope: a file is operated and shaped by its own environment. An outcome test pins that a module's rule does not
   reach a file that does not use it (wiki/use.md: `use` brings in a module).
3. Hygiene: a template's words are resolved in its rule's module. This pays the DEBT at sugar/conditions.wap:44.
4. The artifact: the wap section carries the environment; `use "m.wasm"`, the library and the warm start read it, and
   warm.wap and the text round trip go. It needs a seed refresh, done in three steps: write both formats, read the
   new one, drop the old one.
5. With the switch, the theory's declarations live in the same environment, and the prelude is loaded checked from
   its section instead of being checked again on every run.
6. For the interviewer: a raw word, operator or alias declared in a file applies from its line on, not wherever it
   stands. The text scrape and the whole-tree passes go, and the front reads one statement at a time.

**Risk:** medium.
- It touches pipeline.wap, language.wap, the rule stages, packed.wap, compiler.wap and the seed's format (step 4).
- Step 2 changes a file that relied on a rule leaking into it; the full suite shows which.

### R2. The back end reads run terms

**Now.**
- The emitter (core/emit: 2,081 lines, 1,406 of them code) decides beyond writing each form:
  - it converts closures (function_values.wap);
  - it matches by chains of tests (patterns.wap);
  - it lays out every type (values.wap);
  - it holds the GC build's runtime: 27 routines written as raw instructions, for lists, equality, joining and
    slicing texts, and printing.
- It infers types on wasm layouts, in about 30 places:
  - a function's result from its body (functions.wap:82-92);
  - a local's type from the code emitted into it (patterns.wap:21);
  - a second "does it fit" beside typing's (emitter.wap:257-290).

  The DEBTs at emitter.wap:22 and :258 say so. It also branches on a type's spelling in 16 lines. The guardrail
  emit-infers-type catches none of this.
- The memory build is:
  - 33 branches on `memory`;
  - a library swapped by copying files (extensions/native/build.sh:69);
  - a compile from sources, since the embedded library is the GC one.

  Its runtime is plain wap (types/memory_lists.wap, memory_texts.wap), so the runtime exists twice. The C ABI is a
  third description of layouts: places.wap's C-struct alignment, and the C extension's 66 helper rules that choose by
  a C type's word.
- The theory's run path writes its run terms (an enum of 8 cases, run/terms.wap) as wap source text, with host
  operations as `$k` text templates. Today's compiler reads, binds, types and emits that text again (run/lower.wap).
- The plan (coc-plan 11) bridges this end:
  - R4 lowers run terms into today's kernel forms with layout facts, 300 to 500 lines that R7a replaces;
  - R7a writes "the emitter of erased terms, about 300", while section 5.3 counts the emitter at about 2,000 lines
    rewritten;
  - no step deletes today's emitter.

**Target.**
- Erase gives run terms. Lowering then:
  - converts closures and makes each Choose a decision tree;
  - turns calls in last place into jumps, also in Case arms and Try, which today never get one;
  - puts every value in a local of a known wasm type, its layout read from the build's table of rows.
- The emitter has one case per lowered form and reads no type. wasm.wap, opcodes.wap and the module's assembly stay.
- The runtime is wap over primitives in types/ for both builds, as the memory build's already is.
- A build is its table of rows and its two swap files, chosen by an option of the compiler.

**Deletes and adds** (rough):
- The emitter's upper half, about 1,600 lines with values.wap, becomes about 1,300:
  - lowering, about 500;
  - a thin emitter, about 500;
  - the rows, about 150;
  - the GC runtime in wap, about 150, in place of about 250 lines of instructions.

  That is about −300 net.
- The plan's R4 bridge (300 to 500 lines) is never written.
- run/lower.wap's text and the layouts' check by today's typer go (about 120).

**Unblocks.**
- The plan's R7c: core/analyze can go only once nothing reads its facts, and the emitter reads 12 of them.
- A native build from the embedded library.
- One answer to "does it fit".

**Migration:**
1. The plan's R2, one table of primitives, as planned.
2. The runtime in wap: the 27 routines move to types/ one at a time, written over array and struct primitives. It is
   a pure move, and the emitter shrinks.
3. The plan's R3, the rows: one table per build. values.wap reads its row, the 33 branches go, and a build picks its
   swap files by an option, not by `cp`.
4. In place of the plan's R4: lowering and the thin emitter for run terms, behind the run door's option, reusing
   wasm.wap, the rows and the runtime. The plan's agreement gate (R0) measures them.
5. R7a makes them the default; R7c deletes the emitter's front for kernel forms together with core/analyze.

**Risk:** high, and the same as the plan's.
- The run path today covers small programs of numbers, truth values and function values
  (test/wap/test_theory_run.wap). Parity with lists, texts, maps, records, closures, Try and the host is most of the
  switch, whichever route is taken.
- The bridge reaches parity sooner only by keeping the emitter's own typing, which R7 has to remove anyway. Steps 2
  and 3 make the emitter's knowledge reusable before the first run term is lowered.
- Decide this before the plan's R4 starts.

### R3. The elaborator asks the rules, and reads one lowered statement

**Now.**
- Stage 2, the declaration rules, serves 5 rules in wap/:
  - `$x is $p: predicate` (sugar/types.wap:16);
  - `class … extends` (sugar/records.wap:21);
  - three C rules.
- Stage 3, the typed rules, serves 3:
  - the script's shown value (sugar/calls.wap:15), a mark carried in the code's shape;
  - two `chained` rules.
- Each stage has its own file, round and side effects:
  - declare runs again in each stage-2 round (core/rules/declared.wap:21-23);
  - a typed rule's output is bound and typed again, at no position (core/rules/typed.wap:38-47).
- Decisions are split across stages:
  - `x is w` is decided in four places: stage 1, stage 2, binding and typing;
  - `x.f(y)` passes through four stages;
  - Item does not "leave as a Get" as kernel/surface.wap:4-5 says.
- The theory's elaborator already:
  - reads each statement after the shape rules and lowering, one at a time (elaborate/read.wap:570);
  - resolves names itself, reading no binding fact;
  - reads `enum`, `class` and `trait` as written (elaborate/blocks.wap).

  sugar/records.wap's 54 rules and the Record form exist only for today's typer.
- The plan's section 5.1 has the elaborator read "bound statements", after declare, the declaration rules, lower and
  bind. That is neither today's code nor any milestone's, and R7c deletes scope.wap and declarations.wap, which
  section 5.1 keeps.

**Target.**
- The front ends at lowering one statement.
- A rule whose hole asks a declaration (`$p: predicate`) or a type (`$x: value`) is an elaboration rule. The
  elaborator tries it when it meets the rule's head, with the environment and the expected type at hand, and
  elaborates its output in place, at the position of what it replaced.
- `enum`, `class` and `trait` are declarations of the elaborator.
- The script's shown value is a fact on the program's last statement, not a Prim.

**Deletes and adds** (rough):
- about −230 beyond the plan's own deletions:
  - core/rules/declared.wap and typed.wap: 88;
  - the stage plumbing in the matcher and the rule loader: about 30;
  - sugar/records.wap and the Record form: 101;
  - kernel/surface.wap: 11.
- +40 in the elaborator.

**Unblocks.** One place that decides `x is w` and `x.f(y)`. Typed rules in programs, which test/ writes, see the
environment.

**Migration:** with the plan's R5 to R7.
1. Add the hook in the elaborator; the agreement gate tries it on the 8 rules of wap/ and the 9 of test/.
2. At R7c the two stages go with core/analyze, and sugar/records.wap goes with the Record form.

**Risk:** low. It is the plan's switch with its seam stated right; the plan's section 5.1 and R7c need correcting.

### R4. A gate blocks or goes

**Now.**
- The full suite reports one number: 170 ✗ in 356 tests (test/results.txt, at 49ef9b6e). Behind it:
  - 94 wanted lines, red by design;
  - all 62 scripts of test/wap, failing in that environment ("no wasm2c: the installed wap runs the modules, not this
    tree's"), as in every run whose results name their failures, and their causes are never written down;
  - 7 programs that need the host's network or processes;
  - about 6 failures that are real.
- The guardrails' last local run had 8 of their 16 rules red, with 193 entries over the allowance.
- The size ceiling SIZE_NODES changed in 165 commits since 2026-11-20, each time to the measured value. It records the
  size and limits nothing.
- There are about 32 counters and gates in all.
- The build recipe is written twice, and the two differ in the warm state (test/wap/compile.sh:48-55,
  scripts/refresh-seed.sh:39-53). The native wap is built in three places, and there are four helpers that compile
  and run.

**Target.**
- One runner classes each result as passed, wanted (counted, never blocking), skipped with its reason (a host it
  lacks), or failed.
- A landing is blocked by a failed line alone.
- A floor rises by itself when a run beats it; a ceiling rises only by a commit that names a decision.
- A guardrail is green and blocking, or deleted.
- One build recipe, which refresh-seed.sh calls.

**Deletes and adds:** about −40 lines of duplicated recipes and helpers, +30 in run.sh. What it buys is signal: the
six real failures show.

**Migration:**
1. run.sh classes the results.
2. The ratchets move only by their tool.
3. Each red guardrail is fixed or deleted, with the owner of its rule.

**Risk:** low.

### Parts that need no rewrite

- **The reader and cascade:** a data reader that knows no word, linear since its lists grow in place. Its one
  coupling, the raw words, goes with R1.
- **The operator table and stage:** precedence as relations sorted topologically, aliases as rows, one minus rule.
  With R1 it reads the module's table instead of a global one.
- **The shape rules and lowering:** a pattern and a template over notation is the right macro model, and lowering is
  plain desugaring, one statement at a time.
- **The theory's kernel and elaborator:** they have their own term type and their own names, and they read statement
  by statement (What the plan misses).
- **Facts in Meta:** no rewrite of their own. The 48 fact names go with core/analyze and today's emitter; notation
  keeps the facts of the text.
- **The seed loop:** self-hosted on the native wap. The seed rule is the price every self-hosting compiler pays, as
  Lean's stage0 does, and 29 refreshes since 2026-11-20 kept it moving.
- **The outcome tests:** per wiki page, a page file kept green and a wanted file whose red lines are the work list.
  R4 changes only how results are counted.
- **The native driver and the C extension:** programs of their own on the compiler's output. The C ABI's layouts join
  R2's rows once those exist.

## What the plan misses

**No full rewrite of the typer.** The kernel and the elaborator exist (about 5,600 lines). They have their own term
type, read statements one at a time, and resolve names themselves: finishing the switch beats starting over. What
should be rebuilt in full is the two ends the plan bridges, the environment (R1) and the back end (R2).

Where the plan is wrong or stops short:
1. **The seam** (section 5.1): see R3.
2. **The back end** (R4, R7a, 5.3): see R2. R4 builds 300 to 500 lines that R7a throws away, R7a's 300 lines and
   5.3's 2,000 disagree, and no step deletes today's emitter.
3. **What the switch deletes.** R7c counts core/analyze (3,491 lines) and stops there. Besides R2's emitter and R3's
   stages and records, these lose their reason, about 200 lines more:
   - the binding facts and Signature in core/bindings.wap;
   - most of core/stage.wap's fact names;
   - the warm state's lowered blocks.
4. **The compiled library.** notes/compile_inputs.md wants a compile to need only the library's signatures, its type
   declarations and its rule tables. That cannot hold once library definitions unfold in types and laws: the
   artifact must carry the bodies that may unfold, as Lean's compiled modules do (R1).
5. **The layouts on today's typer.** run/erase.wap:256-312 types each layout's spelling with core/analyze: it prints
   the spelling as source, compiles it, and loads the types module a second time to do so. The plan's R2 removes this;
   until then R7c cannot happen.
6. **The doors.** Only `wap verify` reaches the theory. The other doors are scripts that check the whole prelude again
   on every run. R6 should load the prelude checked, from its artifact (R1, step 5).

| literal defaults | R1, a literal at its expected type | yes, about 10 lines |
| unary nat | nothing to remove: host numerals with shortcuts, as Lean's | keep |
| taking back refused statements | R6 | for the theory; this report's R1 extends it to the front |
| doors | R6 | yes, with the prelude loaded checked (6 above) |
| overloads inside the theory | R5; the kernel already sees unique constants | yes |
| effects against Prop | the elaborator refuses a computation where a value is wanted (9.2) | yes, no kernel change |
| annotations in operated code | not in the plan | the first audit's R1.9, about 5 lines in core/parse; with R1 an annotation that leads a statement belongs to it |

## Appendix: evidence

1. **The environment built by scraping (R1).**
   - core/parse/raw.wap:19-26 finds the raw words by splitting every line of the source on brackets and colons,
     comments included.
   - `import "x"`, a spelling of `use`, is missed by the `use` detection (core/pipeline.wap:86, :95), which looks for
     the text "use " before aliases apply. So x is read after the file that uses it.
2. **Code printed and read back (R1, R2).**
   - A used module's declarations travel as wap source and header lines (extensions/wasm/modules.wap:44-50, 131-138).
   - The run path writes wap text (run/lower.wap).
   - A layout is checked by printing a definition and compiling it (run/erase.wap:305-311).
   - Rules are told apart by their printed text (core/rules/stages.wap:112).
3. **A build made by `cp` (R2).** extensions/native/build.sh:69 copies memory_texts.wap and memory_lists.wap over
   text_bytes.wap and list_items.wap in a copy of the compiler's folder. It then compiles with `--sources`, because
   the embedded types.wasm is the GC one.
4. **Identity by text (R1).**
   - `same_type` compares a type's name (core/analyze/fits.wap:186-189), and Node's `==` ignores Meta, where
     DECLARED_BY lives.
   - An instance's key is the text "<id> <name> <signature>" (core/stage.wap:194-196).
5. **A mark in the code's shape (R3).** sugar/calls.wap:15 marks the script's last statement with `Prim(shown, …)`,
   a stage-3 rule whose Prim the emitter finds by name (core/emit/emitter.wap:68).
6. **A gate that records (R4).** test/wap/ratchet_census.sh's SIZE_NODES went from 100,896 to 142,947 in 165 commits,
   each moving it to the measured value.
