# Audit 2026-11-25 (3): the architecture as a whole

## Target architecture

wap built today, with what is known, has three representations and five steps:

1. **Read.** The data reader turns text into Node and knows no keyword (core/parse/reader.wap, cascade.wap). The
   operator stage reads each phrase by the table of precedence groups.
2. **Elaborate.** First the file's headers are read and its declarations ordered by what each calls, a cycle being
   one block. Then the elaborator walks each statement once. At each node the rules whose head fits are tried first,
   any rule, and a hole of a type is answered by the elaborator itself. Then the node is read. The elaborator binds
   names in its own environment, chooses overloads, puts in conversions and writes complete terms. There are no rule
   stages, and no declare, lower, bind or type pass.
3. **Check.** The kernel accepts each declaration, giving a new environment or a refusal (the plan's R6).
4. **Erase and lower** write the statement language, which is today's kernel forms (kernel/forms.wap). Each node
   carries its layout, the one fact the emitter reads. A prelude constant runs by its row in the one table of
   primitives (the plan's R2). A walk down a recursor becomes a loop again, and a call of the rest becomes an exit.
5. **Emit** reads the statement language, as today's emitter does, and writes wasm with one value layout: GC structs
   and arrays everywhere. A native executable runs the module's machine code, compiled ahead of time by wasmtime
   (.cwasm).

A compiled module, the types module included, is a .wasm with its code and one section holding its environment: its
declarations, rules, aliases and checked generic terms. The compiler, `use "m.wasm"`, the console and the seed read
that and nothing else.

The three representations are Node (what is written), terms (what is checked) and statements (what runs). The theory
is the middle, as the plan has it. Around it, what the plan keeps as it is becomes one each: one rule stage, one
statement language, one layout and one module format.

The tests run in one process, `wap test`, against a baseline of the checks expected red. Scripts test only what a
program cannot: the command line, a terminal and the self build.

## Rewrites, ranked by what they buy

### 1. The tests: one runner, and a baseline of red checks

**Target.** `wap test [area…] [--stage n]` is a command of the native driver. It takes the compiler under test as an
argument (wap1, or wap built of itself n times) and compiles it to machine code once. For each test program it then:
- makes a fresh instance of that compiler, so a refusal or a test's own `rewrite` leaves no trace in the next test;
- compiles the program;
- runs the program in the same engine, under the time cap the driver already has (`--seconds`).

A trap or a timeout is that test's ✗. The console already compiles and runs modules this way, one per line, in one
process (extensions/native/console.wap:3).

A red check is compared with a baseline that names every check expected red, by file and check name.
- A run is green when no check outside the baseline is red.
- A check that turns green leaves the baseline, so the baseline only shrinks.
- A `_wanted` program that does not compile shows each of its check lines as red, by name.

Scripts stay for what a program cannot see: the command line, a terminal and the self build (test_hello, test_self,
test_native, test_guarded).

**Deletes and adds.**
- The runners, test/wap/compile.sh (94 lines), run.sh (106) and scripted.wap (128), become one command of about 150
  lines in extensions/native. Eight ways to compile, run and compare become one (appendix 6).
- The 143 driver checks of the shape `check(name, ran(program), output)` become plain checks in test programs.
- Today each test costs two wap processes and about a dozen helpers: job-slot.sh, nice, guarded.sh's sampler, bash,
  and compile.sh. compile.sh hashes about 4.2 MB of the tree, for every test, to find the shared compiler
  (compile.sh:63). All of that goes.

**Unblocks.**
- A regression is told from a wanted red. This is the gate every other migration here leans on: R0's agreement count
  and each "prints the same both ways" step.
  - Today the full run has 170 ✗ standing (test/results.txt:2409), and run.sh fails on any of them (run.sh:54-55).
  - 92 of the 98 `_wanted` programs do not compile, so 485 of their 492 check lines show as 92 ✗.
- The time goes into processes, not compiling. A fresh compile and run of a small program takes 0.2 s; the suite
  takes 17 to 22 minutes.

**Migration.**
1. `wap test` runs the test programs beside run.sh, and both must give the same ✓ and ✗ per check. The baseline is
   written from that run.
2. The 143 driver checks move into programs. scripted.wap keeps only the checks that need a process of their own.
3. run.sh calls `wap test` for the programs, and compile.sh and the duplicate runners go.

**Risk.** Low.
- The runner lives in the driver, so a bug in it is fixed by rebuilding the driver (compile.sh builds the tree's own).
- Until rewrite 3b the runner is written in the driver's narrower language.
- The cloud run fails every driver today because lib/process.wap:45 reads `_NSGetEnviron`, which only macOS has.
  That is a bug of its own, fixed in lib/. The runner must not route around it.

### 2. The elaborator is the front end: rules fire where it meets them

**Target.** After the switch, a compile is read → operators → elaborate → check → erase → emit. The elaborator
already rewrites a form it cannot read by the shape rules (`respelled`, extensions/theory/elaborate/read.wap:571-575),
lowers each statement (`formed`, :570), and binds names in its own environment (:265-293). This rewrite makes that the
only path:
- At each node, the rules whose head fits are tried first, before the node is read. A rule may match a form the
  elaborator reads too: sugar/calls.wap:15 matches a Block.
- Every rule fires there, not only the shape rules.
- A hole typed `class`, `function` or `predicate` is answered from the environment.
- A hole of a value type is elaborated once. Its term is kept for the template, so no subterm is elaborated twice
  and a failed match leaves nothing behind.
- The header prescan (core/analyze/declarations.wap) becomes the elaborator's first pass. Today the elaborator goes
  unit by unit, in order (elaborate/file.wap:31-41).

**Deletes and adds.**
- Deletes about 160 lines beyond the plan's count:
  - the rule stages 2 and 3: core/rules/declared.wap (32) and typed.wap (56), with the stage numbering of holes
    (core/rules/patterns.wap:51-53, 90; matcher.wap:157);
  - the pipeline's passes that prepare modules, bind, bring in standard words and type: core/pipeline.wap:133-205,
    about 70 lines.
- R7c counts all of declare and bind (890 lines of core/analyze) as deleted, while the plan's own stage table still
  runs them. This rewrite settles which go:
  - the binding: scope.wap, names.wap, variables.wap, definers.wap and library.wap, 593 lines;
  - the prescan and module lookup (declarations.wap 218, modules.wap 79) move into the elaborator instead.
- Adds about 100 lines: rules tried by head at every node, and typed holes answered by an elaboration that is kept.

**Unblocks.**
- The 8 rules of stages 2 and 3 fire under the theory. Today they fire nowhere in it (appendix 1); `extends` and the
  C structs are among them.
- A typed hole works in any rule. The debt "a typed rule sees only its hole's type" goes.
- One rule stage cannot read a group differently from another. Three fixes in three weeks are of that kind
  (appendix 1).
- The walks of the program per compile go from about 16 (appendix 5) to one per step.

**Migration.** Each step keeps the compiler building itself.
1. In the theory, behind its doors: every rule is tried by head, and typed holes are answered by the elaborator.
   Gate: the tests of the 8 rules print the same through the run door, counted by R0's agreement.
2. R7a builds the compiler through elaborate, and the old passes are not on that path.
3. R7c deletes core/analyze, and with it declared.wap, typed.wap and their pipeline passes.

**Risk.** Medium.
- Rules tried at every node cost a lookup per node. Rules are indexed by head today (core/rules/heads.wap), so this
  is a lookup, not a scan.
- Calls written before their definition need the prescan and an order of the declarations (What the plan misses, 2).

### 3. One value layout: native code through wasmtime's ahead-of-time compiler

The GC layout everywhere, in two parts, because the native driver is the embedder of wasmtime itself.

**3a. Programs.** `wap build` writes an executable that runs the program's .cwasm by wasmtime, the way the driver
already runs every program (extensions/native/programs.wap; C imports answered by host_words.wap). It does not use
wasm2c and the memory layout.
- Unblocks native programs written in the full language. A native build refuses enums with fields, maps and `any`
  (core/emit/values.wap:81-82), and it has no try/catch (notes/native.md:29-30). It does not check bounds on `#` and
  `pop` (types/memory_lists.wap:31, 59-63), and it never frees memory (memory_texts.wap:5, memory_lists.wap:7-8).
- Deletes nothing yet: the driver still needs the layout.
- Risk: low.
  - A .cwasm holds for one wasmtime version and one CPU's features, so an executable is rebuilt when wasmtime is.
  - The executable grows by the runtime. Its size is a change the user sees, so it is the user's decision before
    3a lands.

**3b. The driver.** The driver builds C records in memory and calls wasmtime's C API directly (host_words.wap:62-75,
c.wap). As a GC module it would need a C launcher that hands it wasmtime and libc as imports.
- A spike comes first: it measures the launcher's C lines and the driver's start-up time.
- When the spike holds, about 350 lines are deleted, about 125 of them in core:
  - the layout's files: types/memory_lists.wap (70), types/memory_texts.wap (62), extensions/native/memory.wap (22)
    and core/emit/memory.wap (5);
  - its branches in core/emit (values, places, primitives, host, wasm, function_values), core/analyze/data.wap,
    core/language.wap and wap/compiler.wap, about 123 lines;
  - glue.awk (59) and build.sh's wasm2c steps.
- It unblocks the driver written in the full language (appendix 2), and one runtime semantics for every build.
- Risk: high, until the spike measures it. The seed's driver changes, so this takes the careful path.

## What the plan misses

1. **The front end after the switch.** Section 5.1 has the elaborator read bound statements after declare, declared
   rules, lower and bind. Its code does not, and R7c deletes declare and bind while 5.1 keeps them. Rewrite 2.
2. **Calls before their definition.** Today a program calls a function written further down: `print f(2)` with `f`
   and `g` defined after it prints 21. The prescan of core/analyze/declarations.wap is what allows that.
   - The theory elaborates unit by unit, in order (elaborate/file.wap:31-41).
   - A kernel that accepts declarations in order needs each callee before its caller.
   - The plan does not say how this is kept. The elaborator must order a file's declarations by what each calls, and
     read mutual recursion as one block.
3. **The back end is planned three ways:** a new lower (about 800 lines) and an emitter rewritten for run terms
   (about 2,000) in 5.1 and 5.3; erase into the forms today's emitter reads in R4; and an emitter of erased terms
   (about 300) in R7a. R4's route should be the target, not a step. The kernel forms are a good language for what
   runs: blocks, loops and exits, structured as wasm is.
   - **The emitter's contract.** core/emit reads type notation and stage facts in about 30 places. In the target it
     reads one fact per node, its layout, which erase writes from the kernel type. That conversion of about 30
     places is the work; the 2,000-line emitter rewrite is not written.
   - **Lower stays and is risky.** The theory reads a counted loop as a walk down the number type's recursor, and a
     break as a call of the rest after the loop (elaborate/statements.wap:131-188). Lower turns them back into While,
     Break and Continue. Where it cannot, it refuses loudly; it never emits a recursion in place of a loop.
   - **Copies per type.** Section 4 says the per-type copies of a generic function are made after checking. The plan
     names no step that makes them. Erase should, since the layouts are its output.
   - Section 4's row "the emitter reads erased terms" is rewritten to say the same.
4. **The value layouts.** Section 4 says "Unchanged: the wasm value layouts", but there are two. With rewrite 3 first,
   R3's rows are written for the GC layout only. The deadline is R4: erase needs one target.
5. **R6's environment is the module format.** At R7d the one library is compiled once into the module's section, and
   every compile reads it. That joins three ways of carrying a library (appendix 3), and the seed's format changes
   once. Before the switch this buys little, since the old typer types a generic function again for each use.
6. **Classes are read twice.**
   - sugar/records.wap turns `class`, `enum`, `extends` and protocols into Records by rules: 101 lines, and 12 of
     sugar's 30 fixes in three weeks.
   - The theory reads an enum or class unit as written (elaborate/file.wap:1-4, elaborate/blocks.wap), and has no
     `extends` and no protocol.
   - Section 4 calls `extends` "specified, not built", but it is built (sugar/records.wap:21-27).
   - The plan should say that the theory's reading stays. `extends` and protocols then become what the plan says they
     are: a parent's fields with a conversion to it (section 4), and a trait as a structure of its operations
     (section 2).

## What needs no rewrite

- **The data reader** (core/parse/reader.wap, atoms.wap, layout.wap, cascade.wap): Node as the one notation of data
  and code holds.
- **The operator stage.** Its word-role branches are the reader's densest fixes (appendix 4). Most of them are about
  a spaced call after an infix (`1 + count xs`), which a table of keyword phrases would not cover. So there is no
  rewrite before the switch; look again after R7c.
- **The rule engine's core** (patterns, matcher, templates, termination) holds. Rewrite 2 changes when rules fire,
  not how a pattern matches.
- **Sugar** (151 rules) holds: spellings plain wap cannot say, one file per topic. The exception is the class rules
  (What the plan misses, 6).
- **The kernel forms and the emitter** hold as the language that runs, with the layout fact as the emitter's
  contract (What the plan misses, 3). Their one table of primitives is the plan's R2.
- **Facts in Meta** hold. They are a list searched by name and copied on each write (core/stage.wap:96-103,
  wap/nodes.wap:80-83), and they stay the emitter's interface, its layouts, and the notes on written code.
- **The two typers.** The plan's R0 to R7e hold, with the corrections above.
- **The seed and the self-hosting loop** hold. Their cost is the refresh cadence (appendix 7), the price of a compiler
  that uses its own library.
- **The types module** holds. Its twins with the prelude go at R7d, and its swapped list and text files go with
  rewrite 3b.
- **lib/** (84 files, 10,240 lines) holds as the words programs `use`, outside the compiler. One bug: lib/process.wap:45
  works only on macOS (rewrite 1, Risk).
- **Extensions:** c (foreign lines by rules) and prove hold. The theory is the plan.
- **Tooling** holds: the guardrails, compiler-growth.sh, repeated-code.sh and the job slots. The census's size ceiling
  is the exception (appendix 7).
