# Audit 2026-11-25 (3): the architecture as a whole

## Target architecture

wap built today, with what is known, has three representations and five steps:

1. **Read.** The data reader turns text into Node and knows no keyword (core/parse/reader.wap, cascade.wap). The
   operator stage reads a phrase by one table. The operators' precedence groups are rows of it, and so are the
   phrases rules lead (`if … then … else`, `for … in …`). So a word's role (operand, operator or phrase word) is
   decided in one place, by where it stands.
2. **Elaborate.** One walk per statement, after a prescan of the file's headers. Where the elaborator meets a form it
   does not read, the rules rewrite it. Any rule may fire, and a hole of a type is answered by the elaborator itself.
   It binds names in its own environment, chooses overloads, puts in conversions and writes complete terms. No rule
   stages, and no declare, lower, bind or type pass.
3. **Check.** The kernel accepts each declaration, giving a new environment or a refusal (the plan's R6).
4. **Erase and lower** write the statement language, which is today's kernel forms (kernel/forms.wap). Each node
   carries the layout of its kernel type. A prelude constant runs by its row in the one table of primitives (the
   plan's R2). A walk down a recursor becomes a loop again, and a call of the rest becomes an exit.
5. **Emit** reads the statement language, as today's emitter does, and writes wasm with one value layout: GC structs
   and arrays everywhere. A native executable is a launcher holding the module's machine code, compiled ahead of
   time by wasmtime (.cwasm).

A module already compiled has one format: a .wasm with its code and one section holding its environment, which is
its declarations, rules, phrase rows, aliases and generic terms. The types module is such a module. The compiler,
`use "m.wasm"`, the console and the seed read only that format.

The three representations are Node (what is written), terms (what is checked) and statements (what runs). The theory
is the middle, as the plan has it. Around it, the parts the plan keeps as they are each become one: one rule stage,
one statement language, one layout and one module format.

The tests run in one process, `wap test`, against a baseline of the checks expected red. Scripts test only what a
program cannot: the command line, a terminal and the self build.

## Rewrites, ranked by what they buy

### 1. The elaborator is the front end: rules fire where it meets them

**Target.** After the switch, a compile is read → operators → elaborate → check → erase → emit. The elaborator
already expands a form it cannot read by the rules (`respelled`, extensions/theory/elaborate/read.wap:571-575). It
already lowers each statement (`formed`, :570) and binds names in its own environment (:265-293). This rewrite makes
that the only path:
- Every rule fires there, not only the shape rules.
- A hole typed `class`, `function` or `predicate` is answered from the elaborator's environment.
- A hole of a value type is answered by elaborating it and fitting its type.
- The header prescan (core/analyze/declarations.wap) stays, as the elaborator's first pass, for calls written before
  their definition.

**Deletes and adds.**
- Deletes the rule stages 2 and 3: core/rules/declared.wap (32 lines) and typed.wap (56 lines), and the stage
  numbering of holes (core/rules/patterns.wap:51-53, 90; matcher.wap:157).
- Shrinks the pipeline's passes that prepare modules, bind, bring in standard words and type (core/pipeline.wap:133-205,
  about 70 lines) to the elaborator's one walk.
- R7c counts all 890 lines of declare and bind in core/analyze as deleted, while the plan's own stage table (5.1)
  still runs them. This rewrite settles which of them go:
  - The binding goes, because the elaborator binds in its own environment: scope.wap, names.wap, variables.wap,
    definers.wap and library.wap, 593 lines.
  - The prescan and the modules a program uses (declarations.wap 218, modules.wap 79) move into the elaborator. It
    already calls them (elaborate/file.wap:164, 173).
- Adds about 40 lines: the matcher's hole test asks the elaborator. For stage-2 holes it already asks the
  declarations, at matcher.wap:152.

**Unblocks.**
- Under the theory, the 8 rules of stages 2 and 3 fire nowhere today (appendix 1), `extends` and the C structs among
  them. With this rewrite they fire.
- A typed hole works in any rule. The debt "a typed rule sees only its hole's type" goes.
- One rule stage cannot read a group differently from another. That is the class of a06a37fc, 2edabdea and
  bea2d5bc: a block of one phrase opened at one stage and kept at another.
- The walks of the program per compile go from about 16 (appendix 5) to one per step.

**Migration.** Each step keeps the compiler building itself.
1. In the theory, behind its doors: `respelled` tries every rule, and holes of stages 2 and 3 are answered by the
   elaborator. Gate: the tests of the 8 rules print the same through the run door, counted by R0's agreement.
2. R7a builds the compiler through elaborate. The old passes are not on that path.
3. R7c deletes core/analyze, and with it declared.wap, typed.wap and their pipeline passes. Section 5.1 of the plan
   reads read → operators → elaborate.

**Risk.** Medium.
- A rule whose typed hole names something declared later needs the prescan's signatures, so the prescan runs before
  any statement is elaborated.
- The termination check of the rules (core/rules/termination.wap) holds per head. Firing on demand keeps that true.

### 2. The tests: one runner in the native wap, and a baseline of red checks

**Target.** `wap test [area…]` is a command of the native driver. It compiles and runs every test program in one
process: the compiler is instantiated once, the library read once, and each test module runs in the same engine. The
console already works this way, one module per line, linked to the instances it keeps
(extensions/native/console.wap:3).

A red check is compared with a baseline that names every check expected red, by file and check name.
- A run is green when no check outside the baseline is red.
- A check that turns green leaves the baseline, so the baseline only shrinks.
- A `_wanted` program that does not compile shows each of its check lines red by name, not as one ✗.

Scripts stay only for what a program cannot see: the command line, a terminal and the self build (test_hello,
test_self, test_native, test_guarded).

**Deletes and adds.**
- Eight ways to compile a program, run it and compare its output become one (appendix 6). The runners,
  test/wap/compile.sh (94 lines), run.sh (106) and scripted.wap (128), become one command of about 150 lines in
  extensions/native.
- The 143 driver checks of the shape `check(name, ran(program), output)` become plain checks in test programs.
- Per test, today's two wap processes and about a dozen helpers go:
  - job-slot.sh, nice, the sampler of guarded.sh and bash;
  - compile.sh, which hashes about 4.2 MB of the tree for every test to find the shared compiler (compile.sh:63).

**Unblocks.**
- A regression is told from a wanted red. Today the full run has 170 ✗ standing (test/results.txt:2409), and run.sh
  fails on any of them (run.sh:54-55). 92 of the 98 `_wanted` programs do not compile, so 485 of their 492 check
  lines show as 92 ✗.
- The run in the cloud and the run on the Mac test the same thing. In the cloud every driver dies at its start,
  because scripted.wap uses `process`, which reads `_NSGetEnviron` (macOS only: lib/process.wap:45). That is 63 of
  the 170 ✗.
- The time goes into processes, not into compiling: a fresh compile and run of a small program takes 0.2 s
  (measured today), and the suite takes 17 to 22 minutes.

**Migration.**
1. `wap test` runs the test programs beside run.sh, and both give the same ✓ and ✗ per check. The baseline is written
   from a run.
2. The 143 driver checks move into programs; scripted.wap keeps only the checks that need a process.
3. run.sh calls `wap test` for programs, and compile.sh and the duplicate runners go.

**Risk.** Low. One test that traps or loops could take the shared process down: the command runs each module under
the time cap the driver already has (`--seconds`) and reports a trap as that test's ✗.

### 3. One value layout: native code through wasmtime's ahead-of-time compiler

**Target.** Every module uses the GC layout. The native `wap` driver, and each executable `wap build` makes, is the C
launcher (extensions/native/main.c) with the module's machine code embedded (.cwasm) and a wasmtime that only runs.
That is the way the driver already runs everything else: it caches `wap-<hash>.cwasm` and `program-<hash>.cwasm`
(extensions/native/compiler.wap:24-43, programs.wap:1-4), and it links wasmtime statically (build.sh:7-12). wasm2c
goes, and with it the linear-memory layout and the dialect the driver is written in. No reason for wasm2c is
recorded anywhere in notes/ or wiki/.

**Deletes and adds.** Deletes about 350 lines, about 125 of them in core:
- the layout's own files: types/memory_lists.wap (70), types/memory_texts.wap (62), extensions/native/memory.wap
  (22) and core/emit/memory.wap (5);
- its branches in core, about 123 lines: core/emit/values.wap, places.wap, primitives.wap, host.wap, wasm.wap,
  function_values.wap, core/analyze/data.wap, core/language.wap and wap/compiler.wap;
- glue.awk (59) and build.sh's wasm2c steps;
- the cold library read a native build needs because it cannot use the GC library: the swapped files at
  build.sh:67-69.

Adds about 70 lines: the launcher loading an embedded .cwasm (main.c already embeds the seed by `#embed`), and
`wap build` writing launcher and .cwasm.

**Unblocks.**
- The driver can be written in the full language (appendix 2). Today it avoids `list<text>`, maps, `int()`, raise,
  closures and `T?`.
- Native programs get what they lack today:
  - enums with fields, maps and `any` (core/emit/values.wap:81-82 refuses them);
  - try/catch (notes/native.md:29-30);
  - bounds checks on `#` and `pop` (types/memory_lists.wap:31, 59-63);
  - memory that is freed (memory_texts.wap:5, memory_lists.wap:7-8).
- Every build has one runtime semantics.
- A program's C call takes one path. Today it goes wasmtime → C → the wasm2c-built driver → C
  (extensions/native/host_words.wap:62-153).

**Migration.**
1. `wap build` gains the .cwasm route beside wasm2c, and the native tests run both.
2. The driver itself is built by the .cwasm route (scripts/refresh-seed.sh:98).
3. The wasm2c route and the memory layout are deleted. The seed's driver changes, so this takes the careful path.

**Risk.** Low to medium.
- Every executable carries a wasmtime that only runs. Its size is measured before step 1; the driver already pays
  it.
- A native program's run time depends on wasmtime's GC. The benchmarks' guardrails measure it.

### 4. One format for a compiled module: its environment, read once

**Target.** A module wap compiled, the types module included, is one .wasm. It holds its code, for what compiles once,
and one section holding its declarations as packed Node (extensions/packed.wap), already read and declared:
signatures, enums, classes, rules, aliases, operators and generic bodies. The compiler, `use "m.wasm"`, the console
and the seed read that section and nothing else. After the switch, the section holds the environment the kernel
accepted (R6), so a user of a library takes a checked generic term instead of typing its text again.

**Deletes and adds.** Deletes about 150 lines:
- the warm state, extensions/warm.wap (88). Each compiler embeds the library twice: types.wasm (123 KB), plus its
  operated source and lowered form in warm.packed (467 KB). wap1.wasm is 1.48 MB against 0.87 MB for wap0.
- the source-text path of extensions/wasm/modules.wap (`wasm_source`, :44-50, :76-101);
- one of the two section readers (modules.wap:142, extensions/native/linking.wap:37).

Adds about 40 lines: the section written from the declared module.

**Unblocks.**
- A library's generic functions, functions taking functions, classes, enums and rules are read once per library
  build. Today only fully typed functions and globals compile (modules.wap:54-65). The rest is carried as text
  (:76-81), and every importer reads it again, types it and emits it (core/pipeline.wap:174-179).
- `use "m.wasm"` (paused, wasm-module-import) becomes this format's general case.
- With rewrite 3, a native build reads the same library as every other build.

**Migration.**
1. The section is written beside today's, and both are read. Gate: every test program compiles to the same output
   both ways.
2. The compiler's embedded library becomes types.wasm with its section, and warm.wap goes. This changes the seed,
   so it takes the careful path.
3. After R6, the section holds the environment.

**Risk.** Low to medium. The seed's format changes once.

### 5. Phrases are rows of the operator table

**Target.** A rule pattern led by a word (`if $c then $a else $b`, `for $x in $xs $body`, `return $x`) gives the
operator stage a mixfix row:
- its leading word and its inner words;
- where its holes stand, and whether it takes a block;
- a precedence group, like any operator's.

The operator stage reads phrases by these rows as it reads operators: mixfix parsing over a precedence graph (Danielsson
and Norell, "Parsing mixfix operators"). An inner word parts a phrase only while that phrase is open. The rule still
rewrites the phrase's tree as today.

**Deletes and adds.** Deletes about 250 lines and adds about 150. The word-role branches go:
- core/parse/operators.wap `called_after_infix`, `continues_another`, `continuation_item`, `continuation_word`
  and `rule_word` (:150-206);
- tokens.wap `stands_as_name`, `wants_operand` and `operand_after` (:105-127);
- keys.wap `rule_led` and `leads_block` (:12-13);
- core/rules/lines.wap (:16-53);
- the word lists rules tell the reader: `words_told`, core/rules/stages.wap:119-122.

**Unblocks.**
- One mechanism decides phrase structure, where today two do: the operator table and the rules' word lists.
- The word-role fixes stop. That is about a dozen of the 36 reader fixes in three weeks (appendix 4).
- A phrase gets a precedence the reader of a program can know (`a ?? return t`), and format prints a phrase by its
  row.

**Migration.**
1. Rows are built beside the word lists. The operator stage reads every test program and the compiler's source both
   ways, and both must give the same Node; that is a ratchet.
2. The operator stage switches to rows.
3. The word-role branches are deleted.

**Risk.** High. The reader is under everything. A reading today's branches settle without saying, such as a phrase
word that is also a variable (`out`, `text`), becomes a refusal. "Refuse, never guess" wants that, but it can turn
programs red. Step 1's ratchet shows how many.

## What needs no rewrite

- **The data reader** (core/parse/reader.wap, atoms.wap, layout.wap, cascade.wap): Node as the one notation of data
  and code holds. Its fixes are about phrase words in the operator stage (rewrite 5), not about the notation.
- **The rule engine's core** (patterns, matcher, templates, termination): it holds. Rewrites 1 and 5 change when
  rules fire and how phrases are found, not how a pattern matches.
- **The kernel forms and the emitter** hold as the language that runs (What the plan misses, 2). Their one table of
  primitives is the plan's R2.
- **Facts in Meta** are a list searched by name and copied on every write (core/stage.wap:96-103, wap/nodes.wap:80-83).
  They hold for the notes on written code. After the switch, types live in terms and bindings in the environment,
  so facts need no rewrite of their own.
- **The two typers:** the plan's R0 to R7e hold in the order the morning audit gave, with the corrections below.
- **The seed and the self-hosting loop** hold. The 29 refreshes from 11-20 to 11-25 are the price of a compiler that
  uses its own library. Rewrite 4 takes the library's second copy out of it.
- **The types module** holds. Its twins with the prelude go at R7d, and its swapped list and text files go with
  rewrite 3.
- **Extensions:** c (foreign lines by rules) and prove hold. The theory is the plan.
- **Tooling** holds: the guardrails, compiler-growth.sh, repeated-code.sh and the job slots. One exception is the
  census's size ceiling (test/wap/ratchet_census.sh:16). It changed 164 times between 11-20 and 11-25, so it records
  the size; it does not hold it down.

## What the plan misses

1. **The front end after the switch.**
   - Section 5.1 has the elaborator read bound statements after declare, declared rules, lower and bind. Its code
     does not: it reads operated statements, runs the shape rules and lowering on each (elaborate/file.wap:149-150,
     read.wap:570), and binds names itself.
   - R7c deletes core/analyze, which holds declare and bind, while 5.1 keeps them.
   - The 8 rules of stages 2 and 3 fire in no pass after R7c.

   Rewrite 1 settles all three.
2. **The back end is planned three ways:**
   - 5.1 and 5.3: a new lower of about 800 lines, and an emitter rewritten for run terms, about 2,000;
   - R4: erase into the forms today's emitter reads;
   - R7a: an emitter of erased terms, about 300.

   R4's route should be the target, not a step. The kernel forms are a good language for what runs: blocks, loops,
   exits, structured as wasm is. Erase and lower write them, each node with the layout of its kernel type.
   - Lower is still needed. The theory reads a counted loop as a walk down the number type's recursor, and a
     break as a call of the rest after the loop (elaborate/statements.wap:131-188), and lower turns them back into
     While, Break and Continue. It writes forms the emitter already reads.
   - Today's emitter stays. The emitter rewritten for run terms (about 2,000 lines in 5.3) is not written, and R7a's
     emitter of erased terms (about 300) is the same job as R4.
3. **"Unchanged: the wasm value layouts"** (section 4): there are two layouts. Every row of R3 would be written twice,
   and erase would have two targets. Rewrite 3 goes first.
4. **R6's environment is the module format.** At R7d the one library should be compiled once into that format
   (rewrite 4). Today the types module is declared again on every compile (core/pipeline.wap:37).
