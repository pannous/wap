# Audit 2026-11-25 (3): the architecture as a whole

## Target architecture

wap built today, with what is known, keeps most of its shape. The plan's track T is its middle (notes/coc-plan.md
section 11): core/analyze grows into the one elaborator, and the kernel is the only maker of checked facts. Three
things around that middle become one each.

1. **Read, rules, declare, lower, bind**, as today. The data reader turns text into Node and knows no keyword, and the
   operator stage reads each phrase by the table of precedence groups. The passes after it each read one language and
   write one. The three rule stages follow from those passes.
2. **Elaborate.** core/analyze types each statement. Every fact it writes is made by the kernel's rule functions (LCF),
   so what is checked is what runs.
3. **Emit** reads the same statements and their facts, erases types and proofs, and writes wasm with **one value
   layout**: GC structs and arrays in every build. A native executable runs the module's machine code, compiled ahead
   of time by wasmtime (.cwasm).
4. **One module format.** A compiled module, the types module included, is a .wasm with its code and one section
   holding its checked declarations: signatures, enums, classes, rules, aliases, and generic definitions with their
   checked facts. The compiler, `use "m.wasm"`, the console and the seed read that section, and none of them types
   or checks it again.
5. **One test runner.** The tests run in one process, `wap test`, against a baseline of the checks expected red.
   Scripts test only what a program cannot: the command line, a terminal and the self build.

## Rewrites, ranked by what they buy

### 1. The tests: one runner, and a baseline of red checks

**Target.** `wap test [area…] [--stage n]` is a command of the native driver. It takes the compiler under test as an
argument (wap1, or wap built of itself n times) and compiles it to machine code once. For each test program it then:
- makes a fresh instance of that compiler, so a refusal or a test's own `rewrite` leaves no trace in the next test;
- compiles the program;
- runs the program in the same engine, under the time cap the driver already has (`--seconds`).

A trap or a timeout is that test's ✗. The console already compiles and runs modules this way, one per line, in one
process (extensions/native/console.wap:3).

A red check is compared with a baseline that names every check expected red, by file and check name.
- A run is green when no check outside the baseline is red.
- A check that turns green leaves the baseline, so the baseline only shrinks.
- A `_wanted` program that does not compile shows each of its check lines as red, by name.

Scripts stay for what a program cannot see: the command line, a terminal and the self build (test_hello, test_self,
test_native, test_guarded).

**Deletes and adds.**
- The runners, test/wap/compile.sh (94 lines), run.sh (106) and scripted.wap (128), become one command of about 150
  lines in extensions/native. Eight ways to compile, run and compare become one (appendix 5).
- The 143 driver checks of the shape `check(name, ran(program), output)` become plain checks in test programs.
- Today each test costs two wap processes and about a dozen helpers: job-slot.sh, nice, guarded.sh's sampler, bash,
  and compile.sh. compile.sh hashes about 4.2 MB of the tree, for every test, to find the shared compiler
  (compile.sh:63). All of that goes.

**Unblocks.**
- A regression is told from a wanted red. Each step of track T lands "with the compiler building itself", and every
  "prints the same" gate needs that signal.
  - Today the full run has 170 ✗ standing (test/results.txt:2409), and run.sh fails on any of them (run.sh:54-55).
  - 92 of the 98 `_wanted` programs do not compile, so 485 of their 492 check lines show as 92 ✗.
- The time goes into processes, not compiling. A fresh compile and run of a small program takes 0.2 s; the suite
  takes 17 to 22 minutes.

**Migration.**
1. `wap test` runs the test programs beside run.sh, and both must give the same ✓ and ✗ per check. The baseline is
   written from that run.
2. The 143 driver checks move into programs. scripted.wap keeps only the checks that need a process of their own.
3. run.sh calls `wap test` for the programs, and compile.sh and the duplicate runners go.

**Risk.** Low.
- The runner lives in the driver, so a bug in it is fixed by rebuilding the driver (compile.sh builds the tree's own).
- Until rewrite 2b the runner is written in the driver's narrower language.
- The cloud run fails every driver today because lib/process.wap:45 reads `_NSGetEnviron`, which only macOS has.
  That is a bug of its own, fixed in lib/. The runner must not route around it.

### 2. One value layout: native code through wasmtime's ahead-of-time compiler

Every build uses the GC layout. This comes in two parts, because the native driver is itself the program that embeds
wasmtime.

**2a. Programs.** `wap build` writes an executable that runs the program's .cwasm by wasmtime, the way the driver
already runs every program (extensions/native/programs.wap; C imports answered by host_words.wap). It does not use
wasm2c or the memory layout.
- Unblocks native programs in the full language. A native build refuses enums with fields, maps and `any`
  (core/emit/values.wap:81-82), and has no try/catch (notes/native.md:29-30). It does not check bounds on `#` and
  `pop` (types/memory_lists.wap:31, 59-63), and it never frees memory (memory_texts.wap:5, memory_lists.wap:7-8).
- Deletes nothing yet: the driver still needs the layout.
- Risk: low.
  - A .cwasm holds for one wasmtime version and one CPU's features, so an executable is rebuilt when wasmtime is.
  - The executable grows by the runtime. Its size is a change the user sees, so it is the user's decision before 2a
    lands.

**2b. The driver.** The driver builds C records in memory and calls wasmtime's C API directly (host_words.wap:62-75,
c.wap). As a GC module it would need a C launcher that hands it wasmtime and libc as imports.
- A spike comes first: it measures the launcher's C lines and the driver's start-up time.
- When the spike holds, about 350 lines are deleted, about 125 of them in core:
  - the layout's files: types/memory_lists.wap (70), types/memory_texts.wap (62), extensions/native/memory.wap (22)
    and core/emit/memory.wap (5);
  - its branches in core/emit (values, places, primitives, host, wasm, function_values), core/analyze/data.wap,
    core/language.wap and wap/compiler.wap, about 123 lines;
  - glue.awk (59) and build.sh's wasm2c steps.
- It unblocks the driver written in the full language (appendix 2), and one runtime semantics for every build.
- Risk: high, until the spike measures it. The seed's driver changes, so this takes the careful path.

## What the plan misses

These are about notes/coc-plan.md on main: track T, one typer grown in place.

1. **A checked library carried once.** The plan names compile time as a risk ("Every fact is now built through the
   kernel", section 10.5), and meets it only with a gate: the self-build may grow by a fifth per step.
   - **Today.** The types module is declared again on every compile (core/pipeline.wap:37). Only fully typed
     functions and globals of a library compile. Generic functions, classes, enums and rules travel as text, and
     each importer types them again (extensions/wasm/modules.wap:54-101, core/pipeline.wap:174-179).
   - **Under track T** each of those typings builds its facts through the kernel, on every compile that calls the
     word.
   - **The remedy is the module format of the target (4).** A library is compiled once with its checked
     declarations in its section, and every compile reads them without checking them again.
   - **Cost.** It deletes about 150 lines: the warm state (extensions/warm.wap; each compiler carries the library
     twice, appendix 3), the source-text path of modules.wap and one of its two section readers. It adds about 100:
     the checked declarations written and read.
   - **It needs one decision of the user's.** A compiled library is trusted as the kernel accepted it when it was
     built, and `wap check` alone checks it again, as a second checker does for Lean's compiled files.
   - **When.** It lands with T5, when definitions become kernel declarations. The seed's format then changes once.
2. **Two value layouts.** Section 4 lists "the wasm value layouts" as unchanged, but there are two. T5's erasure in
   the emitter and T8's storage by context both decide what a value is stored as. With two layouts each is written
   twice, or the memory layout refuses more. So rewrite 2 goes before T5.
3. **`extends` and protocols.** Section 4 calls `extends` "specified, not built". It is built, by rules
   (sugar/records.wap:21-27), and the class rules are 12 of sugar's 30 fixes in three weeks. T5 makes classes into
   inductive blocks and T6 makes traits into structures, but neither names `extends` or protocols. Each needs a line:
   a parent's fields with a conversion to it (section 4), and a protocol read as a trait.

## What needs no rewrite

- **The data reader** (core/parse/reader.wap, atoms.wap, layout.wap, cascade.wap): Node as the one notation of data
  and code holds.
- **The operator stage.** Its word-role branches are the reader's densest fixes (appendix 4). Most of those fixes are
  about a spaced call after an infix (`1 + count xs`), which a table of keyword phrases would not cover. No rewrite;
  look again after T5.
- **The rule stages, declare, lower and bind** hold with core/analyze grown in place.
  - The three rule stages follow from the separate passes: a stage-2 rule needs declare's work, a stage-3 rule
    needs typing's.
  - Their cost is about 88 lines of stage machinery for the 8 rules of stages 2 and 3, and about 16 walks of the
    program per compile (appendix 1, 6).
  - A Lean-style elaborator that binds, expands rules and types in one walk would remove both. The theory's
    elaborator works that way (extensions/theory/elaborate/read.wap:265-293, 570-575), but only by putting binding
    into typing, which track T does not plan.
  - So there is no rewrite. The self-build time gate shows whether the walks matter.
- **The rule engine's core** (patterns, matcher, templates, termination) and **sugar** (151 rules) hold. The class
  rules are the exception (What the plan misses, 3).
- **The kernel forms and the emitter** hold as the language that runs. Track T keeps them, and its T1 is their one
  table of primitives.
- **Facts in Meta** hold. Under track T they carry the kernel's judgements on every typed node. They are a list
  searched by name and copied on each write (core/stage.wap:96-103, wap/nodes.wap:80-83), so the self-build gate will
  show their cost first. An index by name is the remedy if it does.
- **The two typers** become one by track T, which holds.
- **The seed and the self-hosting loop** hold. Their cost is the refresh cadence (appendix 7), the price of a compiler
  that uses its own library.
- **The types module** holds. Its twins with the prelude go at T7, and its swapped list and text files go with
  rewrite 2b.
- **lib/** (84 files, 10,240 lines) holds as the words programs `use`, outside the compiler. One bug: lib/process.wap:45
  works only on macOS (rewrite 1, Risk).
- **Extensions:** c (foreign lines by rules) and prove hold.
- **Tooling** holds: the guardrails, compiler-growth.sh, repeated-code.sh and the job slots. The census's size ceiling
  is the exception (appendix 7).
