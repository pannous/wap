# Audit 2026-11-26: the architecture as a whole

Read at bb869988, against notes/coc-plan.md track T. In place there: T1, T1b, T2 (the kernel in wap/kernel), TM1
to TM3 (one grammar per module), T3a (the unifier in core/analyze) and T3b (types as kernel terms). Paths are under
wap/ unless they start with notes/, wiki/, test/ or scripts/. "Probed" means compiled by the tree's own wap1 and run
by the native wap.

## Target architecture

wap built today, with what is known, has the shape track T is growing: one typer, a small kernel that accepts every
declaration, and an emitter that decides nothing. Under all of it sits one thing the plan takes for granted and the
compiler does not have: a memory model in which a name never sees a change made through another.

1. **Values.** A text, a list, a map, a record and a case are values.
   - `xs.add(v)`, `xs += v`, `xs#i = v` and `p.x = v` change the variable they name, so `xs += v` is `xs = xs + v`.
   - A function that changes a parameter gives it back.
   - The compiler updates in place where the old value is never read again, and copies otherwise.
   - A reference is written: a `shared` cell, and writing it is State.

   This is what makes statements pure terms (coc-plan 9.5), an environment persistent and a take-back a plain "keep
   the old value".
2. **The front**, as today. The data reader knows no word, and the operator stage reads phrases by the table of
   precedence relations. Then come the shape rules, declare, the declared rules, lower and bind. A module is read in
   its own grammar, built from the modules it uses, and a declaration applies from its line on.
3. **One environment per module, as one value.** It holds the front's declarations (operators, aliases, raw words,
   rules, records, signatures) and the kernel's (declarations by id).
   - Declaring returns a new environment or a refusal.
   - A compiled module carries it in its wap section, and `use "m.wasm"`, the warm start and the seed read that one
     format.
4. **One typer: analyze, bidirectional.**
   - A type is a hash-consed kernel term, and what a program leaves out is a hole of one unifier.
   - Trust sits at the environment: the kernel accepts each finished declaration, checked whole.
   - A node's facts are the typer's own and are not trusted.
5. **Each word defined once.** A definition is the word's meaning; `@runs` beside it says what the program runs. The
   trust base is the set of declarations with a run body, printed by a command.
6. **Erase** is a stage of its own. It removes types, levels and proofs, and gives each value its layout, a row of
   the build's table.
7. **Emit** has one case per form and reads rows. It infers no type and reads no type's spelling.
8. **Tests are one command.** It compiles and runs each program with the compiler under test, lists the known reds
   once, and fails only on a change. Each gate a step relies on is a script.

Today against it:
- **In place:**
  - the reader, the operator table and the rule engine;
  - a grammar per module (TM1 to TM3);
  - types as terms (T3b) and the unifier in analyze (T3a);
  - the kernel in wap/kernel, with ids, i64 numbers and a fresh check of each declaration (T2);
  - one table of host operations and the layouts as rows (T1, T1b);
  - the baseline of reds.
- **Not in place:**
  - values (R1);
  - the plan's description of where trust sits (R2);
  - one definition per word (R3);
  - the environment as one value: the grammars, the kernel's log with take-backs, the Signatures, the type-term
    table and the warm state are separate;
  - erase as a stage;
  - the compiled library carried once;
  - gates that are scripts (What the plan misses, 7).

## Rewrites, ranked by what they buy

### R1. One memory model: values, changed in place only where no other name sees them

**Now.** wap has two memory models, and the plan is built on the one the compiler does not have.
- **The compiler shares** (probed, appendix 1).
  - `zs = [1, 2]; ws = zs; ws#2 = 8; print zs` prints `[1, 8]`. That is the example wiki/Footguns.md "Aliasing"
    says leaves zs unchanged.
  - `d = c; d += 3` changes c, while `b = a + [2]` leaves a alone, so `x += y` and `x = x + y` mean different
    things. types/lists.wap:46-49 grows the list in place "so a name sharing xs sees them".
  - A record or a list given to a function and changed there is changed for the caller.
  - A record stored in a map and changed afterwards is changed in the map, and `q = p; q.x = 5` changes p.
- **The wiki says both.**
  - wiki/list.md:222: "Lists and maps are shared like instances". test/test_lists_page.wap:28-31 pins it.
  - wiki/Footguns.md:455-463: "value semantics … nothing is mutated in place, so all three examples leave x/a
    unchanged". It has no test, and it lists aliasing as the footgun of Python, JS and Java that wap avoids.
- **The compiler's own source relies on sharing.**
  - core/pipeline.wap:132-144 stores a Grammar in language.grammars and goes on growing it ("a use back while it is
    read finds this one, still growing").
  - The kernel changes its Environment and its Checker through their parameters (kernel/environment.wap:278-291
    `back_to`, kernel/typing.wap:59-61 `concluded`).
  - wap/core has about 139 field writes and 73 in-place list and map calls; wap/kernel has 24.
- **The plan assumes values.**
  - Section 4 lists "value semantics (wiki/Footguns.md "Aliasing")" among what stays unchanged.
  - Section 9.5 makes statements pure terms on that premise: "`xs#i = v` and `p.x = v` give the variable the updated
    value (value semantics)".
  - Section 2 makes a class a structure with eta, which is a value.
  - T5 turns "blocks, variables, loops and exits" into kernel terms by 9.5. E5's test is `total([1, 2, 3]) == 6` by
    `refl`.
- **What follows if T5 and T6 land as planned.**
  - `grown() := { xs = [1]; ys = xs; ys.add(2); xs }` returns `[1, 2]` today (probed).
  - By 9.5 its term computes `[1]`, so `law grown() == [1]` is proved by computing while the program gives `[1, 2]`.
  - 10.2's "a proved law holds for the running program" then fails, and the law run on values shows FAILED beside
    Proved.
- **Taking back has the same cause.** State changed in place must be undone by hand. Eleven mechanisms do it, and
  seven more places save a value and put it back (appendix 2).
  - Only the kernel's step counter is put back when something raises (kernel/environment.wap:379-388).
  - So `wap format` after a refusal reads the program in the refused file's grammar: compiler.wap:95-98 catches the
    refusal that skipped read_in's restore (core/pipeline.wap:149-152).
  - A kind rule whose output raises leaves its round counter one higher (core/rules/typed.wap:43-45).
  - A restarted typing round shares `members` with the round it dropped, and `TYPES` and `typed_readings` keep that
    round's entries (core/analyze/types.wap:172-179).

**Target: mutable value semantics**, as in Hylo (formerly Val), Swift's value types, and Lean 4's in-place update of
a value nothing else holds.
- Every value is a value. A name never sees a change made through another.
- A write changes the variable it names.
- A function that changes a parameter gives it back, and the caller's variable takes the new value. This is an inout
  parameter, found from the function's writes: 9.5's receiver rule applied to every parameter.
  `based(language, file)` is written as today.
- The compiler changes a value in place where the old value is never read again: a variable's last use, or an inout
  argument. Otherwise it copies. A copy is what aliasing costs, and it never changes a result.
- A reference is written: a `shared` value is a cell, and writing it is State (9.5 names it already). The class
  setters and signals the user accepted today are such cells.

The decisive point is where the alias analysis sits.
- **Under values**, "this write may happen in place" is the emitter's optimisation. 10.2 already trusts the emitter
  for what runs, and a cautious analysis only copies more.
- **Under sharing**, "this write is seen by no other name" is the elaborator's decision, and it shapes the term a law
  is proved about.
  - A missed alias proves a false law about the running program. That puts the analysis in the trust base, against
    5.5 ("a bug anywhere else … cannot make a false law pass").
  - A cautious analysis makes the function State, and its laws cannot be proved.

**Deletes and adds** (rough):
- **Adds about 310:**
  - the last-use and inout analysis in analyze, about 250;
  - the emitter's copy at a write whose old value is still read, about 40, over the copy words the types module
    has;
  - `shared` as a types word with its rule, about 20.
- **Deletes about 90 in core and kernel now:**
  - the kernel's `mark`, `back_to`, `kept_if_given` and `taken_back`;
  - holes.wap's and unify.wap's take-backs;
  - read_in's held grammar.

  The theory's `held`, `copied` and `Snapshot` go with T5 as planned, and never need porting.
- **Source changes:**
  - the compiler's alias-reliant sites, found by step 2 below;
  - types/lists.wap's two `+=`;
  - wiki/list.md:222 and test_lists_page.wap:28-31, a spec change through the interviewer.

**Unblocks.**
- T5's statements as terms, with what is checked being what runs.
- T2's environment as the plan states it: "checking a declaration gives a new environment or a refusal, so a
  refused statement needs no rollback".
- Ownership inference as notes/purpose.md wants it ("immutable values by default; unique mutable values when
  provable … without changing source semantics"). The compiler may borrow, move or copy, because none of it is
  visible.
- A native build frees a value at its last use. Today types/memory_lists.wap:7 and memory_texts.wap:5 never free.
- One meaning for `+=`.

**Migration**, each step building itself:
1. The user chooses values or sharing, and both wiki passages and the test then say one thing.
2. The analysis lands reporting only: a note for each write whose old value another name may still read.
   - Run over wap's own source, its notes are the inventory of alias-reliant sites.
   - Each site is rewritten so it works under both rules, threaded or as a `shared` cell, before the rule changes.
     This keeps the seed rule.
3. The emitter copies at those writes and gives inout parameters back.
   - The benchmarks and the `--stage 2` time gate guard it.
   - A seed refresh carries it.
4. The kernel's Environment becomes a value. `kept_if_given` keeps the old value, and `mark` and `back_to` go.
5. T5 builds on it.

**Risk:** high, and the choice is the user's, about the spec.
- Every program that relies on sharing changes its result: test_lists_page.wap:28-31, and whatever step 2 finds in
  lib/.
- Compile time rises where the analysis is weak and maps get copied; the stage-2 gate measures it.
- The seed: until step 3 lands, the compiler's source must work under both rules, so step 2 rewrites it first.

**If the user keeps sharing,** 9.5 changes instead.
- A write through a value another name may hold is State.
- The elaborator needs a may-alias analysis that must be exact, because it is in the trust base.
- Laws about functions with such writes cannot be proved.

That costs less now (about 200 lines in T5), but it keeps the take-backs and the analysis in the trust base.

### R2. Trust at declarations, as the kernel is built: a node's facts stay the typer's

**Now.** The plan and the kernel draw the trust boundary in different places.
- **The plan** (5.1, 11 track T, 13) wants LCF on every node:
  - "A node's fact holds the number of a judgement in the kernel's table and is read back only through the kernel";
  - "elaborate builds every fact through the kernel's constructors (LCF), so nothing checks the statements a second
    time";
  - "the facts the stages write on nodes are those checked facts".
- **The kernel as built** checks each finished declaration whole.
  - `declared` (kernel/typing.wap:169-181) makes a fresh checker and judges the declaration's type and value from
    scratch.
  - The only other way in is an inductive block, through `declared_together` and inductive.wap's own checks.
  - An elaboration has a checker of its own (core/analyze/holes.wap:37-40). Its memo of judgements (`judgements` and
    `judged`, kernel/environment.wap:346-348) is a cache for that one elaboration, and each premise in it passes
    through the elaborator's `filled_in` (kernel/typing.wap:29), which is untrusted code.
  - A TYPE fact is a place in the compile's type-term table (core/type_notation.wap:83-84, 133), never a judgement
    number, and no T row still delivers one.
- This is Lean 4's model: the elaborator types with the kernel's rules as it goes, and the kernel checks the finished
  declaration again, whole. It is also what 10.1 says: "every term is checked whole".

**Target.** Keep what is built, and say so in the plan.
- Trust attaches to the environment: a declaration is trusted because the kernel accepted it whole.
- A node's facts (its type as a term, the reading chosen, the instance) are the typer's, and untrusted, like any
  stage's. They need no judgement number and no rule that they are read back through the kernel.
- The emitter reads the statements of accepted declarations, so what is checked is what runs.

**Deletes and adds.** No code changes. It deletes planned work and one constraint:
- the judgement number on every node from T3 to T6, and the discipline of reading it back;
- the soundness reason the T3 row gives for one pass ("a discarded round would leave checked judgements behind").
  One pass is still worth building, but for speed;
- a fact dropped when typing rebuilds a node (832fb550: typing dropped a `@shown` mark) stays that stage's bug and
  never becomes a hole in the trust base.

**Unblocks.** Each of T3 to T6 is a change to the typer, and the kernel's acceptance of the finished declaration is
its only gate for trust. A wrong fact on a node can refuse a good program, or make the kernel refuse a declaration.
It cannot make a false law pass.

**Cost.** Each declaration is judged twice: once while it is elaborated, and once whole. The stage-2 gate measures
it. If that costs too much, the remedy is the kernel's own speed (interned terms, 10.5), not handing the elaboration's
memo to `declared`:
- That memo outlives the elaboration's take-backs. `back_to` restores the environment
  (kernel/environment.wap:278-291) and holes.wap's `taken_back` restores the holes, but neither touches the checker's
  `judged`.
- So a judgement made before a take-back can name a constant that is gone, because `judgement` asks the memo before
  `constant_rule` checks that the constant is live (kernel/typing.wap:23-33, 72-73).
- The fresh check refuses such a term today ("unknown name"). A shared memo would accept it.

**Risk:** low. It is the code as it stands, and the plan's own 10.1.

### R3. One definition per word, its run body beside it: the trust base derived

**Now.**
- **Ten twins.** These words are defined once in the theory's prelude
  (extensions/theory/prelude/operators.wap:17-25 and :33) and once in the types module (types/prelude.wap:39-41, :58
  and :70-75; types/texts.wap:39):
  - int's `+`, `*`, `==`, `<`, `<=`, `>` and `>=`;
  - int's `-`, with one argument and with two;
  - text's `+`.

  A twin is found by the shown text of its header (extensions/theory/elaborate/declare.wap:359 `same_signature`,
  with :176-185 and :300-366). Proofs read the prelude's body, and the program runs the types module's. Only a law
  run on values relates the two.
- **Nineteen more names are declared on both sides with other meanings.** `filter` makes a subset type in the prelude
  and filters a list in the types module, and add, count, drop, keys, list, map, set, sum, text and nine more do the
  same. They become overloads of one name.
- **Thirty-one layouts.** The prelude writes `runs(…)` statements, 14 of them a `prim`.
  - elaborate/file.wap:84 and :98-118 read them, and so does run/erase.wap.
  - Only the run door checks them (erase.wap:277-354).
  - The 17 that are no `prim` are typed by core's typing. That goes against T1's row: "no wap spelling of a host
    operation is typed or checked".
- **The trust base is a hand list** (notes/theory.md:314-341), and it has already drifted. Line 333 places text's `+`
  in types/text_bytes.wap, but it is wap code in types/texts.wap:39. T1's row promised a command that lists it, and
  none exists.
- **The plan joins nothing.** T3e moves the numbers prelude into wap/types beside its twins and deletes neither copy.
  T7 says the words "now live once in wap/types", but no step says how.

**Target**, the way Lean marks a definition `implemented_by`:
- A word is declared once, in wap/types. Its definition is its meaning: the kernel checks it and unfolds it in proofs.
- `@runs <body>` beside the definition is what the program runs: a `prim` of T1's table, or a wap body. The kernel
  never reads it; erase picks it.
- The trust base is exactly the declarations with a run body. A command prints it from the environment, and a law
  about such a word is also run on values (10.2).
- A `prim` with no definition, like `print`, stays an opaque constant.

**Deletes and adds** (rough):
- **Deletes about 120:**
  - the twin matching, about 31 code lines;
  - the `runs(…)` statement and its readers, about 50;
  - one side of each twin, about 20;
  - the hand list in notes/theory.md.
- **Adds about 45:**
  - `@runs` read where definitions are declared, about 15 (core/analyze/declarations.wap);
  - erase and the emitter taking the run body, about 15;
  - the command, about 15.

**Unblocks.**
- T3e lands the numbers prelude as definitions with run bodies, not as a second copy.
- T7's "the words live once" gets its step.
- The trust base can no longer drift from the code.

**Migration**, each step building itself:
1. Declare reads `@runs` on a definition.
   - The program runs the attached body, and the definition is typed, and checked once T5 makes definitions
     declarations.
   - A leading annotation already attaches to its phrase (core/parse/cascade.wap:62 and :103,
     test/test_rules.wap:85-93), but nothing reads `@runs`.
2. The command lists the declarations with a run body.
3. At T3e the ten twins become ten declarations in wap/types: the prelude's definition, with the types module's
   `prim` as its `@runs`. `same_signature` and its callers go.
4. Each of the nineteen shared names becomes one word or two. That is a word choice, made through the interviewer.
5. The prelude's other `runs(…)` become annotations as their words move, at T5 and T7.

**Risk:** low. A run body that disagrees with its definition is caught by the laws run on values, as today.

### What needs no rewrite

- **The data reader and its cascade.** Node as the one notation of data and code holds. TM tells the pipeline each
  line before it is read. One scan is not yet true: the raw words are still read from every line, in about four
  passes (core/parse/raw.wap:20-27), and a `use` line is read twice (core/pipeline.wap:72-73).
- **The operator stage.** Precedence as relations sorted topologically, aliases as rows, one minus rule. TM gave each
  module its own table.
- **The rule engine and sugar.** Patterns, matcher, templates and termination hold. The rule stages follow from the
  passes: a declared rule needs declare's work, a kind rule typing's. Hygiene (DEBT sugar/conditions.wap) is still
  open.
- **The stages and their facts.** Facts in Meta hold, and under R2 they carry the typer's facts and need no trust.
  Their cost is visible:
  - A compile walks the program 18 times (appendix 6).
  - A new fact copies the fact list twice (wap/nodes.wap:80-87), and `with_facts_of` is quadratic in a node's facts
    (core/stage.wap:57-62).

  An index by name is the remedy when the stage-2 gate trips.
- **Types as terms (T3b).** One representation, read at one door, compared by `==` of places. The table is the
  compile's own, as a symbol table is. Its ids still need joining to the kernel's (What the plan misses, 5).
- **The kernel.** Lean's rules, constants by id, i64 numbers with an overflow check, and a fresh check of every
  declaration. Its step and depth budgets are 6.7's design, not unary numbers: a numeral opens one successor at a
  time only where no shortcut fires.
- **The emitter.** T1 and T1b did what they promised, apart from the two gaps below. What is left goes with erase:
  34 branches on a build keeping its values in the memory, the emitter's own typing (functions.wap:87-91,
  patterns.wap:22, emitter.wap:260-273), and 17 comparisons with a type's spelling. That is planned for T5.
- **The seed and the self-hosting loop.** 31 refreshes since 11-20. T2, TM and T3b changed nothing the seed reads, so
  no refresh was due.
- **The extensions.** native, c, wasm and prove hold. The theory shrinks by the user's removal (option a) and by T3
  to T7.
- **Two value layouts.** The user's decision stands. The cost shows in What the plan misses, 9.

## What the plan misses

1. **The memory model.** Section 4 lists value semantics as unchanged, and 9.5 and T5 build on it, but the compiler
   shares (R1). The choice comes before T5.
2. **Where trust sits.** 5.1, the T track and 13 describe node judgements. The kernel checks declarations whole, as
   10.1 says. The plan should say what is built (R2).
3. **T1's row is open on two points.**
   - "The emitter finds an operation by one lookup": `primitive_code` (core/emit/primitives.wap:65-90) dispatches 18
     ways, as many as before T1. Five tables remain, among them `text_operations`, which has gained `ref.eq`.
   - "The trust base listed by a command from the `runs(…)` declarations": there is no such command (R3).
4. **T2's row says the environment is persistent**, "so a refused statement needs no rollback". T2 built an
   environment changed in place and taken back (notes/coc-t2.md "One environment, changed in place"), and eleven
   take-back mechanisms remain (appendix 2). TM2 added one: read_in's held grammar, core/pipeline.wap:148-154. R1
   makes the row true.
5. **Two id spaces for one constant.** `TYPES.words` gives a type word an id from 1 (core/type_notation.wap:83-90).
   The kernel's log gives a declaration an id from 1 as well.
   - A type term from analyze names constants no environment holds.
   - Before T3e or T3f hand such a term to the kernel, the two spaces must be one, or one id means two declarations.
     10.4 calls that pitfall "two terms taken for one".
6. **Two nats, and no term for an `int` numeral.**
   - The kernel types every numeral as the numbers declaration's type, which must be an inductive
     `enum nat { zero; successor(n: nat) }` (kernel/typing.wap:106, kernel/numbers.wap:54).
   - T3e makes a numeral an `int` where nothing else is wanted, but says no term for it.
   - T4 makes `nat` be `int where it >= 0`, which is a second nat beside the kernel's.
   - The plan should say that the kernel's numeral type is the types module's inner carrier, that an `int` numeral is
     `int.of_nat` of it, and that the subset is the `nat` programs write.
7. **The gates are not scripts.**
   - Every T step is accepted by "`--stage 2` a fixed point", but no script checks one: test_self.sh:40-47 only
     times, and refresh-seed.sh:70 only reports.
   - The speed shares of coc-t3.md and integrator.md:88's +20% have no script either.
   - In the reds baseline, a `_wanted` file that does not compile is one line, so 94 files hide 496 checks, and "no
     new red" cannot see inside them.
   - The cloud suite shows 7 regressions.
   - notes/backbone.md asks for gates "measured by a script, never by eye" (user 2026-11-18).
   - The suite now takes 38 to 49 minutes because the scripts run on the cloud host; before, they failed fast. test_self.sh
     alone takes the last 8.6 minutes. Each program costs about 60 processes, 2 of them wap.
8. **The bridge grows.** The work into extensions/theory added 402 lines and deleted 110 (d3ad4b63, 245c4eb2,
   84033ffd and T1's part), and no twin is gone. T3g is planned bridge work too. Every bridge line is deleted again by
   T7; R3 joins the twins instead of matching them.
9. **The memory layout gained a form.** The decision says "the memory layout keeps the forms it has". native-maps-2
   (2a7eeaf5) gave it maps: a layout row, the map words in types/memory_lists.wap:74-91, and a typing branch in
   core/analyze/data.wap:129, 284 nodes in all. It landed as a "standing OK small fix", while
   notes/open_decisions.md:16 still lists native maps for the user. Branches on the memory build went from 32 to 34.
10. **`int` wraps until T8, and for good if cut 9 is taken.** notes/theory.md:325 says so. 10.2's table says a proved
    law holds for the running program, and should carry this exception beside cut 9.
