# Audit 2026-11-27: the architecture as a whole

Read at f05e43fb, with branch t5u-unions (3410aa94: T4a, T4b, T5u and notes/coc-t5.md, approved and waiting to
land) read beside it. Paths are under wap/ unless they start with notes/, wiki/, test/, lib/ or scripts/; section
numbers are notes/coc-plan.md's. "Probed": compiled by the tree's wap1 (data/wap-tests/wap1-fbf49adde7365760, the
build of f05e43fb), run by its native wap (appendix 1).

## Target architecture

1. **The front as today:** the data reader gives Node, the operator table reads operators, the rules (shape,
   declaration, kind) rewrite spellings, lowering writes the general forms; each module is read in its own grammar.
2. **One elaborator:** analyze types each function instance once, bidirectionally; a type is a kernel term; an
   overload is chosen once, by the conversion order, before anything reaches the kernel.
3. **What runs is the statements as written** (9.7), compiled one case per form; the kernel checks their translation
   (9.5), which is believed for what runs and listed so in 10.2; every law is also compiled and run on values by the
   same compiler, so a disagreement shows as FAILED beside Proved (R1).
4. **One meaning for a write** (R2): values, as 9.5, wiki/Footguns.md and purpose.md say; sharing is the compiler's
   choice wherever no other live name can see the write; `shared` is the reference a program writes.
5. **The kernel's door names only what the kernel accepted** (R3): a definition or a T1 row. A function that writes,
   raises, may not end or acts on the world carries that as a fact from the moment it is typed (wiki/effects.md) and
   stays a constant no law names until its computation type exists (9.1, 9.6).
6. **Trust at declarations:** the kernel accepts each finished declaration whole; the facts on nodes are the
   elaborator's, untrusted.
7. **Each word declared once** (card definition-one): its definition is its meaning, `@runs` names its host
   operation or layout.
8. **A compiled module carries what the kernel accepted:** its declarations, its grammar's rules and its erased
   code; the warm state, the compiled library, `use "m.wasm"` and the seed are that one artifact.
9. **Tests are one command against one baseline per host**, and every gate a landing relies on runs in it.

In place: 1, 2 (letters.wap still beside the unifier), 3's emitter, 6 as built (T3b's type places, T3f's
constants), 7's mechanism. Missing: 3's law run and its line in 10.2, 4, 5, 7's joining, 8 (T5g), 9's scripted gates.

## Rewrites, ranked by what they buy

**One finding behind the three.** The program runs its statements as written: 9.7, "Each constant runs by its
statements as written, the ones the emitter reads", and section 5's stage table (emit reads "the statements and their
checked facts"). The kernel checks a translation of them, 9.5's. The plan also says the opposite: section 11's T5 row
has the emitter erase "types, levels and proofs from the checked terms", and notes/coc-t5.md's T5f copies it ("the
emitter reads checked terms") with a budget, +200/−150, that is the size of reading statements; reading terms would
be a new backend, recursors and folds turned back into loops. 10.2 trusts the elaborator for neither column, resting
the second on 9.7's theorem for a recursive body, and a loop or a write has no such theorem: nothing equates a written
loop with its fold, so for what runs the translation is believed. Once section 11's T5 row, T5f and 10.2's table say
so, three places remain where the kernel's picture of a program and its run can part, each needing its net:
- nothing compiled runs a law, so nothing tests the translation (R1);
- a write through a second name is a new value in the picture and shared in the run (R2);
- a function that writes or acts is a pure constant in the picture (R3).

### R1. A law runs as the program runs

**Now.**
- **"Tested" is the kernel's:** extensions/theory/elaborate/tested.wap:1-3, "each of its parameters takes small
  values of its type, and the kernel computes the statement on each". It computes the theory's term, so it sees
  neither the emitter, nor the prims, nor `int`'s wrapping, nor 9.5's translation. A build erases every law
  (extensions/laws.wap:3, `rule law $statement... => ()`): nothing compiled ever runs one.
- **Its values come from a plain enum only** (tested.wap:39-41, `tried_values`): a `nat` or a `bool` law can fail; an
  `int`, text or list binder gives no value, and a law without binders no instance (tested.wap:34-37). Probed: `law
  broken(n: nat): n * n > n` is FAILED, while `law two: 2 + 2 == 5`, `law square(2) == 5`, `law sq(x: int):
  square(x) == x + x` and `law square(x) == x + x` are Untested, and `law square(x) >= 0` is Proved. A law over
  `float` refuses the whole file, the theory having refused the prelude's `float` (appendix 1).
- **The spec wants the run:** wiki/law.md:10, a law is "tested where it can be"; test/wap/test_proof_wanted.wap:9,
  red, wants `law tested(x: float): x * 1.0 == x` Tested.
- **The twins' host spellings and layouts** are recorded and read by no reachable code: run/erase.wap's
  `layouts_checked` has no caller, against notes/theory.md:303-305.
- **The plan counts on the run and builds it in no step:** 10.2, "Every proved law is still run on test values
  against the compiled program. A prelude function that disagrees with the host operation it runs by shows as FAILED
  beside its Proved." T6's row ("a plain compile proves by computing, else the law is Tested") says nothing of the
  compiled run. The run is the only net under 10.2's second column for the twins (card definition-one), the memory
  model (R2), a constant that hides an effect (R3), `int` wrapping until T8 and 9.5's translation.

**Target.** A law is two things read by one elaborator: a proposition the kernel proves (Proved), and a test the
compiler compiles and runs on values of its binders' types (Tested; FAILED with the counterexample). Proved beside
FAILED is 10.2's alarm. The kernel's computing stays the cheap counterexample finder until the run covers every law.

**Deletes and adds**, no line in core, about 100 to 150 in all:
- `wap verify` compiles each law as a function of its binders, a closed law as one of none, by a rule beside
  extensions/laws.wap's erasing one (a build keeps erasing laws; sugar/ takes nothing while T runs; its commit says
  `spec: wiki/law.md` for scripts/compiler-growth.sh): about 10;
- trial values as library words, for `int` (its edges included), `nat`, `bool`, text, a list by its items and an enum
  by its cases: 50 to 80; a class by its fields needs a word that lists them;
- the run, and its verdicts joined with the kernel's, in extensions/native: 30 to 50;
- tested.wap (97 lines, extension) goes once every Proved law also runs.

Not counted: the types of the binders a law leaves unwritten (`law square(x) == x + x`), the theory's until T5a (it
reads `x` as `int`), analyze's after. A statement that does not compile to a `bool` stays Untested.

**Unblocks.** law.md's promise and test_proof_wanted's line 9; every T5 step's translation checked by running; the
twins' net before definition-one joins them; R3's refl over a writing function shown FAILED.

**Migration**, each step building itself:
1. Closed laws and laws whose binders are written run, beside the kernel's computing, each with its own verdict
   where the theory refuses the file (the `float` law).
2. Laws whose binders the theory types run too, those binders written from its types.
3. Every Proved law also runs; tested.wap goes.

**Risk:** medium: which binders get a type, which statements run, trial values per type. `wap verify` only: a build
and its tests change in nothing.

instances as references: (a)'s analysis for lists, maps and texts, the Grammar's and the Environment's take-backs

interviewer.

### R3. The door names only what the kernel accepted; effects by T5b

**Now.**
- **Every typed function is an opaque constant of a pure function type:** since T3f each instance enters the
  compile's environment by its signature, a Pi type, "added unchecked" as a DeclarationKind.Axiom
  (core/analyze/calls.wap:594-603, core/type_notation.wap:110-116, 194), whatever it does: one that writes its
  parameter, prints or raises alike; one that only raises has the result `never` (calls.wap:593). It is an assumption
  on purpose: `TYPES.assumed` counts it, calls.wap:594-595 says "what rests on it rests on an assumption", and T5's
  gate wants none assumed.
- **No law reaches one today:** a function type's domain is the opaque parameter tuple `and`/`none`
  (core/type_notation.wap:25-26), which has no constructor, and `wap verify` reads programs through the theory's own
  reader, which refuses statement forms (appendix 1).
- **T5a opens the door and says what enters, not what may be named:** "the theory's door reads analyze's typed
  nodes" (notes/coc-t5.md, row T5a), and its pure forms ("literals, calls of known definitions, `if`, `let` blocks,
  `and`/`or`, and the number and text primitives") decide which bodies become definitions; "a function with any other
  form stays opaque". The row does not say what stops a law, a proof or a type argument read through the door from
  naming such a constant.
- **What such a law would claim, by running:** `pure_looking(xs) := { xs.add(1); #xs }` makes `pure_looking(l) ==
  pure_looking(l)` print `no`, and so does `random() == random()`; to the kernel each side is one term, equal by
  refl. With `grow(xs) := { xs.add(1); 0 }`, `grow(xs) + #xs` gives 2 and `#xs + grow(xs)` gives 1 on the same
  `[5]`, equal by `int`'s commutativity. No probe has the kernel prove one: the door is not open yet.
- **`never` is an opaque word:** were T4 or T5u to make it the empty type, every raising function's constant would
  prove anything.
- **The gates check effects before the plan builds them:** section 11's T5 row and coc-t5.md's T5b, T5c and T5d
  check `effects of` ("`effects of fact` is Pure", "`effects of` a `while` without a measure is Div");
  notes/coc-t4.md:23-24 and 102 move T4's Fail line to T6, "which brings effects", and section 11's budget counts
  them in T6's 500 analyze lines ("effects, instances, laws, tested"); no T5 step counts a line for them. T5's gate,
  every function of wap's source "defined or Div, none assumed", cannot hold while a function that prints or writes
  through a parameter gets its computation type only at T6.
- **The spec has them:** wiki/effects.md "Model": "The compiler finds a function's effects itself … `effects of f`
  names them"; test_effects_wanted's four `effects of` checks are red; `print(effects of f)` is "nothing defines this
  name". The only effect inference is the theory's own (extensions/theory/elaborate/effects.wap, 243 lines,
  computation types included), on its own reading of the program.

**Target.**
- **The door:** a term T5a's door builds names only declarations the kernel accepted and T1's rows; an assumed
  constant is refused by name (`law f(l) == f(l)` on a writing `f`: f is assumed, not defined). The rule covers
  `never` and a function that only calls itself too.
- **Effects, by T5b:** each typed instance carries an `effects` fact, the effects wiki/effects.md names (State, IO,
  FFI, Async, Div, Eval, Fail; Allocation reported, no effect). Its roots are the prims, one effect each in T1's row
  (the WASI imports IO; division, `unreachable` and the raising helpers Fail; the list, map and field writes a write
  of their first operand); the body adds its own forms (`raise`, a `while` with no measure and a recursion Div until
  T5c, `global`, `emit`); a call adds the chosen instance's effects; a function value of its own type `fn<key>` its
  instance's, one typed by a signature what the signature writes, else all. A recursive group is joined until it
  holds. `try` removes Fail. A write through a parameter, a capture or a global is State until R2 decides what a
  write means. `effects of` prints the fact, a written `! IO` is checked against it.
- **T5's gate** then reads: every function of wap's source defined, Div, or opaque by a named effect until T6.

**Deletes and adds.** The door's rule: a few lines inside T5a's +180, and its outcome line. The effects: about 150
core (about 110 in a new core/analyze/effects.wap: the join, the body's forms, recursion; 10 in kernel/primitives.wap,
the effect per row; 30 for `effects of` and the claims), moved from T6's budget into T5b's, so no total changes. The
inference half of the theory's effects.wap (about 120 lines) goes once the theory reads analyze's nodes, the rest with
T6, which keeps only turning the facts into computation types.

**Unblocks.**
- T5a sound by the door's rule alone, with no reorder of the track.
- T5b to T5d's `effects of` lines; test_effects_wanted's four checks and test_errors_wanted's "effects of a function
  that can fail name Fail, try removes it"; T4's Fail line back at T4.
- T5's gate true as written above.
- What wiki/effects.md promises pure code: folding, memoizing, dropping an unused pure call.

**Migration**, each step building itself:
1. T5a's door refuses an assumed constant by name, its line in T5a's gate.
2. The prim rows get their effect; nothing reads it yet.
3. analyze writes `effects` on each instance; the census prints how many functions have each effect.
4. `effects of` and the `!` claims, by T5b: test_effects_wanted's checks go green.
5. T6 makes the facts computation types.

**Risk:** low: the door's rule is a refusal; a missed effect prints a wrong `effects of` and, from T6 on, would let a
law through, which R1's run shows FAILED. Moving effects from T6 to T5b changes the user-approved plan, so it goes to
the user through the interviewer with these counts.

### What needs no rewrite

- **The reader and the operator stage:** Node holds as the one notation; precedence as relations, aliases as rows,
  a grammar per module (TM) hold.
- **The rule engine and sugar:** patterns, matcher, templates and termination hold; T5 deletes ROUNDS_LIMIT.
  The declaration words (`type`, `rule`, `pattern`) are read only on a statement of their own (appendix 6).
- **Stages and facts:** one walker, facts beside the shape. Names cost a quarter of the self-compile
  (notes/speed.md: text equality 14%, hashing 10%, `fact_of` 7%, `meta_unwrapped` 4%); fact names as numbers in
  place of texts is a speed card, not a restructuring.
- **Types as terms and one unifier:** in place (T3b, T3c); letters.wap stays as the letter holes until T5.
- **Unions (T5u):** they reuse any's boxing and T4's narrowing; no new mechanism.
- **The kernel:** Lean's rules, constants by id, i64 numbers with an overflow check; untouched by T3 to T5u.
- **The emitter:** one case per form; T5f takes the build's branches (80 lines in core, appendix 3). Of the plan's
  three strategies, "call_ref or a table" has no branch: both layouts call through the table
  (core/emit/function_values.wap:75), CALL_REF is unused and notes/backbone.md still says call_ref.
- **Two value layouts:** the user's decision; their twin library files (80 lines) are the price, as decided.
- **The seed loop:** the fixed point is a script now (test/wap/test_self.sh: wap2 is wap1's bytes).
- **The extensions:** native, c, wasm and prove hold; the plain compile reaches no file of the theory or the provers
  (only `wap verify` does, through verify.wasm), and the theory shrinks as T5 deletes its elaborate/. run/erase.wap
  (353 lines) and run/terms.wap (44) are reached by nothing, kept as T5's reference by the user's decision.
