# Audit 2026-11-27: the architecture as a whole

Read at f05e43fb, with branch t5u-unions (3410aa94: T4a, T4b, T5u and notes/coc-t5.md, approved and waiting to
land) read beside it. Paths are under wap/ unless they start with notes/, wiki/, test/, lib/ or scripts/. "Probed":
compiled by the tree's wap1 (data/wap-tests/wap1-fbf49adde7365760, the build of f05e43fb), run by its native wap
(appendix 1).

## Target architecture

1. **The front as today:** the data reader gives Node, the operator table reads operators, the rules (shape,
   declaration, kind) rewrite spellings, lowering writes the general forms; each module is read in its own grammar.
2. **One elaborator:** analyze types each function instance once, bidirectionally; a type is a kernel term; an
   overload is chosen once, by the conversion order, before anything reaches the kernel.
3. **Effects are a fact of every instance from the moment it is typed** (R1): what it writes, whether it may raise,
   may not end or acts on the world, found from the prims and the body's forms up, as wiki/effects.md specifies.
   The kernel gets a function as a definition only when it has none of them; laws speak of those alone (9.1, 9.6).
4. **One meaning for a write** (R2): values, as 9.5, wiki/Footguns.md and purpose.md say; sharing is the compiler's
   choice wherever no other live name can see the write; `shared` is the reference a program writes.
5. **Trust at declarations:** the kernel accepts each finished declaration whole; the facts on nodes are the
   elaborator's, untrusted.
6. **What runs is what was elaborated:** the emitter compiles the elaborated statements whose terms the kernel
   accepted, by 9.5's rule per form, which (4) makes true; every law is also compiled and run on values by the same
   compiler, so a disagreement shows as FAILED beside Proved (R3).
7. **Each word declared once** (card definition-one): its definition is its meaning, `@runs` names its host
   operation or layout.
8. **A compiled module carries what the kernel accepted:** its declarations, its grammar's rules and its erased
   code; the warm state, the compiled library, `use "m.wasm"` and the seed are that one artifact.
9. **Tests are one command against one baseline per host**, and every gate a landing relies on runs in it.

In place: 1, 2 (letters.wap still beside the unifier), 5 as built (T3b's type places, T3f's constants), and 7's
mechanism. Missing: 3, 4, 6's law run, 7's joining, 8 (T5g), 9's scripted gates.

## Rewrites, ranked by what they buy

### R1. Effects as facts, before T5a

**Now.**
- **Every typed function is an axiom of a pure function type to the kernel.** Since T3f each instance enters the
  compile's environment by its signature, a Pi type, "added unchecked" as a DeclarationKind.Axiom
  (core/analyze/calls.wap:594-603, core/type_notation.wap:110-116, 194), whatever it does: one that writes its
  parameter, prints, raises or loops alike; one that only raises has the result `never` (calls.wap:592).
- **Today that is harmless only by accident:** a function type's domain is the opaque parameter tuple `and`/`none`
  (core/type_notation.wap:25-26), which has no constructor, so no term can apply such a constant; and `wap verify`
  reads programs through the theory's own reader, which refuses statement forms (appendix 1).
- **T5a ends both** (notes/coc-t5.md on t5u-unions, row T5a): definitions whose "body unfolds when a type or a
  condition computes with it", and "the theory's door reads analyze's typed nodes". Its purity is a list of forms,
  "literals, calls of known definitions, `if`, `let` blocks, `and`/`or`, and the number and text primitives".
- **Probed:** `pure_looking(xs) := { xs.add(1); #xs }` makes `pure_looking(l) == pure_looking(l)` print `no`, and so
  does `random() == random()`; to the kernel both sides are one term, equal by refl. With `grow(xs) := { xs.add(1); 0 }`,
  `grow(xs) + #xs` gives 2 and `#xs + grow(xs)` gives 1 on the same `[5]`, equal by int's commutativity.
- **The plan has the rule, at the wrong step:** 9.1 and 9.6 let a type or a proof use only functions with no effect
  but Fail, and 9.2's argument that an opaque constant needs no axiom rests on computation types being inhabited;
  T3f's axioms have plain signatures. Effects come with T6 ("effects are computation types"), after T5a, T5c (Div)
  and T4's Fail check (moved to T6 by notes/coc-t4.md "Gate") need them.
- **The spec has them now:** wiki/effects.md "Model": "The compiler finds a function's effects itself … `effects of f`
  names them"; test_effects_wanted's four `effects of` checks are red; `print(effects of f)` is "nothing defines this
  name". The
  only effect inference is the theory's own (extensions/theory/elaborate/effects.wap, 243 lines, computation types
  included), on its own reading of the program.

**Target.** Each typed instance carries an `effects` fact: the effects wiki/effects.md names (State, IO, FFI, Async,
Div, Eval, Fail; Allocation reported, no effect). Its roots are the prims, one effect each in T1's row (the WASI
imports IO; division, `unreachable` and the raising helpers Fail; the list, map and field writes a write of their
first operand); the body adds its own forms (`raise`, a `while` with no measure and a recursion Div until T5c,
`global`, `emit`); a call adds the chosen instance's effects; a function value of its own type `fn<key>` its
instance's, one typed by a signature what the signature writes, else all. A recursive group is joined until it
holds. `try` removes Fail. A write through a parameter, a capture or a global is State until R2 decides what a write
means. `effects of` prints the fact, a written `! IO` is checked against it.

**Deletes and adds.** Adds about 150 core: about 110 in a new core/analyze/effects.wap (the join, the body's forms,
recursion), 10 in kernel/primitives.wap (the effect per row), 30 for `effects of` and the claims. Deletes nothing in
the compiler now; the inference half of the theory's effects.wap (about 120 lines) goes when the theory reads
analyze's nodes (T5a), the rest with T6. T6 keeps only turning the facts into computation types.

**Unblocks.**
- T5a, sound: an effect-free instance (or a Fail-only one, as `T or Error`) becomes a definition; every other one
  stays opaque and a law naming it is refused, "laws speak of pure code" (9.2).
- test_effects_wanted's four `effects of` checks, and test_errors_wanted's "effects of a function that can fail name
  Fail, try removes it".
- T4's "`effects of` a function with a check left is Fail" back at T4; T5c refines a fact that exists.
- R2's inventory: every function that writes through a parameter or a capture, by name.
- What wiki/effects.md promises pure code: folding, memoizing, dropping an unused pure call.

**Migration**, each step building itself:
1. The prim rows get their effect; nothing reads it yet.
2. analyze writes `effects` on each instance; the census prints how many functions have each effect.
3. `effects of` and the `!` claims; test_effects_wanted's checks go green.
4. T5a reads the fact in place of its list of forms, keeping the list only as the forms it can translate.
5. T6 makes the facts computation types.

**Risk:** low to medium. One more fact per instance (the self-compile is measured as every step's is); an effect
the join misses would let a law through, which R3's runs catch. It reorders the user-approved track T, so it goes to
the user through the interviewer, with its core lines.

### R2. One meaning for a write, decided before T5d

**Now.** As notes/audit/2026-11-26.md R1 found, and still so (appendix 1): the compiler shares (`ws = zs; ws#2 = 8`
changes zs; a function that adds to its list parameter changes the caller's list; `q = p; q.x = 5` changes p), while
9.5, the plan's section 4 ("Unchanged: … value semantics") and wiki/Footguns.md "Aliasing" promise values, and
wiki/list.md:223 promises sharing. No card, no plan line and no decision record the question.

**What changed is the date it bites:** notes/coc-t5.md puts statements at T5d ("a variable's new value a new
binding") and classes at T5e ("its fields projections"), both after T5a. 9.5's receiver rule makes `ys = xs;
ys.add(2); #xs` the term 1 where the program gives 2 (2026-11-26's `grown()`, probed again).

**Target and options:** as 2026-11-26 R1, leaning (a), values everywhere: it is the model in which a weak analysis
costs speed and never a proof, and the one purpose.md asks for ("without changing source semantics").

**Migration:** R1's facts replace 2026-11-26's first step: the functions with State from a write through a
parameter or a capture are the inventory, by name, over wap's own source and lib/. Then the user chooses (the wiki's
two pages and test_lists_page.wap then say one thing), and the reported sites are rewritten before T5d.

**Deletes and adds, risk:** as 2026-11-26 R1: under (a) about 90 lines of take-backs go and the copy decision is
added in erase or emit; about 236 sites of the compiler's own source change. High risk, the spec's.

### R3. A law runs as the program runs

**Now.**
- **"Tested" is the kernel's:** extensions/theory/elaborate/tested.wap:1-3, "each of its parameters takes small
  values of its type, and the kernel computes the statement on each". It tests the theory's reading of the program,
  never the compiled program; a build erases every law (extensions/laws.wap:3, `rule law $statement... => ()`), so
  nothing compiled ever runs one. The layouts and hosted spellings the twins carry are recorded and read by no
  reachable code: run/erase.wap's `layouts_checked` has no caller, against notes/theory.md:303-305.
- **In the plain spelling a false law is Untested:** `law square(2) == 5` and `law square(x) == x + x` both say
  Untested, while `law square(x) >= 0` is Proved (appendix 1). wiki/law.md:10: a law is "tested where it can be";
  test/wap/test_proof_wanted.wap:10, red: "a broken law shows its counterexample".
- **The plan counts on the run:** 10.2, "Every proved law is still run on test values against the compiled program.
  A prelude function that disagrees with the host operation it runs by shows as FAILED beside its Proved." That run
  is the only net under 10.2's second column for the twins (card definition-one), the memory model (R2), `int`
  wrapping until T8 and 9.5's translation.

**Target.** A law is two things read by the same elaborator: a proposition the kernel proves (Proved), and a test
the compiler compiles and runs on values of its binders' types (Tested; FAILED with the counterexample). Proved and
FAILED together is the alarm 10.2 names.

**Deletes and adds.** Adds about 60: a rule beside sugar/definitions.wap:53 making a law with binders a function of
them, trial values as library words (int, nat, bool, text, a list by its items, a class by its fields), and
`wap verify` running the compiled tests (extensions/native). Deletes tested.wap (97 lines, extension) once the
theory reads analyze's nodes (T5a).

**Unblocks.** law.md's promise and test_proof_wanted's line; a check of every T5 step's translation by running;
the twins' net before definition-one joins them.

**Migration:** 1. laws with written binders (`law broken(n: nat): …`) run now, beside the kernel's computing;
2. at T5a, laws whose binders analyze finds run too, and tested.wap goes; 3. every Proved law is also run.

**Risk:** low: `wap verify` only, no compile changes.

### What needs no rewrite

- **The reader and the operator stage:** Node holds as the one notation; precedence as relations, aliases as rows,
  a grammar per module (TM) hold.
- **The rule engine and sugar:** patterns, matcher, templates and termination hold; T5 deletes ROUNDS_LIMIT.
  The declaration words (`type`, `rule`, `pattern`) are read only on a statement of their own (appendix 6).
- **Stages and facts:** one walker, facts beside the shape. Names cost a quarter of the self-compile
  (notes/speed.md: text equality 14%, hashing 10%, `fact_of` 7%, `meta_unwrapped` 4%); fact names as numbers in
  place of texts is a speed card, not a restructuring.
- **Types as terms and one unifier:** in place (T3b, T3c); letters.wap stays as the letter holes until T5.
- **Unions (T5u):** they reuse any's boxing and T4's narrowing; no new mechanism.
- **The kernel:** Lean's rules, constants by id, i64 numbers with an overflow check; untouched by T3 to T5u.
- **The emitter:** one case per form; T5f takes the build's branches (80 lines in core, appendix 3). Of the plan's
  three strategies, "call_ref or a table" has no branch: both layouts call through the table
  (core/emit/function_values.wap:75), CALL_REF is unused and notes/backbone.md still says call_ref.
- **Two value layouts:** the user's decision; their twin library files (80 lines) are the price, as decided.
- **The seed loop:** the fixed point is a script now (test/wap/test_self.sh: wap2 is wap1's bytes).
- **The extensions:** native, c, wasm and prove hold; the plain compile reaches no file of the theory or the provers
  (only `wap verify` does, through verify.wasm), and the theory shrinks as T5 deletes its elaborate/. run/erase.wap
  (353 lines) and run/terms.wap (44) are reached by nothing, kept as T5's reference by the user's decision.
