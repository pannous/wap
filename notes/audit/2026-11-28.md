# Audit 2026-11-28: the architecture as a whole

Read at 5cd65e54, with origin/t5b-effects (867a2535, not merged) read beside it. Paths are under wap/ unless they
start with notes/, test/, lib/ or scripts/; section numbers are notes/coc-plan.md's. "Probed": compiled by the tree's
build (data/wap-tests/wap1-8423669c7190848f) and run by its native wap; "the kernel alone" is that build's
bin/wap-seed/verify.wasm, the half of `wap verify` that gives the kernel's verdicts (appendix 1). Landed since
2026-11-27's report (f05e43fb, 610 commits): one typer (unify-typers), enums and bool as kernel blocks, courses and
products in core, traits (C1a), the law run with its stamps, modules and a seed without source, machine words,
failable values, and the decision that a write is shared (9.5).

## Target architecture

What reads a program, in order, and what each part may trust:

1. **The front as today:** the data reader gives Node, the operator table reads operators, the rules rewrite
   spellings in three stages, lowering writes the general forms; each module is read in its own grammar.
2. **One elaborator** types each function instance once, bidirectionally; types are kernel terms; an overload is
   chosen once, by identity; a conversion is the call of a declared function (R3); one unifier.
3. **Each instance knows what it does:** its effects are a fact from the moment it is typed; a write through a
   parameter, a capture, a global or a second name is State (9.5: sharing, decided).
4. **What the kernel holds is true of the run** (R1): a function enters as a definition only when it ends, has no
   effect and calls only definitions and checked rows; any other enters with a type that says so (9.1's computation
   type), and until that type exists it is named by no proposition, proof or obligation. Every door asks the kernel
   one question: whether the declaration it uses is defined.
5. **What runs is the statements as written** (9.7); the kernel checks their translation, believed for what runs.
6. **A law is elaborated once and judged twice** (R2): the kernel proves the declaration, the same compiled function
   runs on trial values, law by law, each with its own trap and time; a Proved law that fails when it runs is a
   verdict of its own.
7. **Identity by number from bind on** (R4): definitions, kernel declarations and facts carry numbers; the core's
   own declarations live apart from a program's names; the kernel's environment is persistent.
8. **Each word declared once,** its host row attached; the trust base listed by a command from the rows, the axioms
   and the stamps a program believes.
9. **A compiled module carries what the kernel accepted** (T5g): declarations, rules, erased code, and verdicts that
   rest on 4.
10. **Measures hold the plan to its sizes** (R5): each landing reports the compiler's size against the ballpark, and
    each step's gate checks its deletions.

In place: 1, 2 but for conversions and the second unifier, 5. On a branch: 3 (t5b-effects). Missing: 4, 6, 7, 8's
command, 9, 10.

## Rewrites, ranked by what they buy

### R1. What the kernel holds is true of the run

**Now.**
- **The kernel proves laws about functions that write, raise or never end** (appendix 1):
  - With `pure_looking(xs: list<int>) := { xs.add(1); #xs }`, the kernel alone proves `law same(l: list<int>):
    pure_looking(l) == pure_looking(l)` by refl; the run finds `l = [1, 1]`.
  - With `stop(n: int) as int := { raise "no" }`, `law s(n: int): stop(n) == stop(n)` is Proved, and so is it in
    `wap verify`'s output, the run having trapped.
  - With `spin(n)` looping in `while yes`, `law u(n: int): spin(n) == spin(n)` and `law v(n: int): spin(n) + 0 ==
    spin(n)` are Proved, and `wap verify` never ends.
- **The spec says the opposite:** wiki/effects.md:81, "A proof (`refl`, `wap check --strict`) refuses a function that
  is not pure, naming the chain"; 9.5 gives a function that writes through a parameter State, "its laws are Tested,
  never Proved"; 9.6 lets a proof use a function with Div or a world effect "by its type only, and only inside a
  computation".
- **The root:** instance_entered (core/analyze/terms.wap:44-62) enters every function the form test cannot read as an
  axiom at a pure function type (`axiom_added(…, signature ?? type)`), whatever it does; 9.1 and 9.2 make such a
  function one into a computation type, which does not exist yet. And a call is a pure form whatever its callee:
  called_term takes the constant instance_entered gives, an assumed one too (terms.wap:105-112), so a law's function
  over an assumed callee is a definition. verify's refusal reads only the law's own function
  (extensions/verify/laws.wap:129): `law same2: pure_looking([5]) == pure_looking([5])`, whose list literal makes its
  own function assumed, is refused naming pure_looking, while `same` is proved. The first assumed callee is found
  (TypedLaw.assumed, laws.wap:68, 160-174), and only that message reads it.
- **What hides it:** `wap verify` joins the kernel's verdict and the run's by the law's name and prints the run's
  FAILED in place of a Proved (extensions/native/driver.wap:129-139), so a Proved law that fails when it runs, which
  that comment calls a wrong translation, never shows as such; and one law that raises takes the run's verdicts with
  it, so the kernel's Proved is printed alone (R2).
- **Where it would spread:** "A proved obligation loses its run check" (coc-plan.md, after T6a3a) writes PROVED
  facts that drop run checks in a module the check door writes; V3 makes proved laws facts for later obligations; a
  compiled module's wap.laws stamps are believed by every importer (driver.wap:115-120). Each would carry such a
  Proved into code that runs.
- **Effects exist only on a branch:** origin/t5b-effects (28 commits, core/analyze/effects.wap 238 lines) writes an
  EFFECTS fact per instance; neither terms.wap nor verify reads it there.
- **A second unchecked entry:** a host operation's row enters the environment by `added`, which skips the kernel's
  check (terms.wap:121), and a program's own `prim` has the type its definition writes (core/analyze/types.wap:
  597-602): `less(a: int, b: int) as int := prim i64.lt_s(a, b)` holds a row whose meaning gives a truth at type
  int. No probe turned it into a wrong verdict.

**Target.** The environment holds only what is true of the program as it runs:
- **closure:** a definition calls only definitions and checked rows; a function that calls an assumed one is assumed
  itself, so an assumption spreads up the calls, and verify, the check door, V3 and the stamps each ask the kernel one
  question, whether the declaration they use is defined. This is the sound stand-in for 9.2's computation types
  until they exist;
- **effects:** with the effect fact, the refusal names what the function does (State, IO, Fail, Div), not "it may
  write, raise or act", which it prints today for float's `==` (appendix 1). A function with no effect that ends is a
  definition once the form test reads its body (a match with T5b4, an ending recursion with T5c, statements with
  T5d); until then it stays assumed, and nothing names it;
- **rows:** a row is checked against its T1 row and its meaning's type before it is added.

**Deletes and adds.**
- Step 1: core about +1, called_term giving no term for a callee declared as an assumption; its outcome lines: the
  kernel alone refuses `same`, `s` and `u` naming their assumed callee, and `wap verify` prints `same` FAILED with its
  counterexample, never Proved.
- Step 1's cost is unmeasured: the census's floor of 1,010 defined instances (test/wap/ratchet_census.sh:18-19,
  "only more may come") falls by however many definitions call an assumed function, and the laws Proved today over
  such a callee turn Tested. The builder measures both before the verdict.
- Step 2: kernel about +5 (a row checked against its meaning's type).
- Step 3, after t5b-effects: terms.wap about +5 (the refusal names the effect), verify about −5 (its own refusal
  becomes the kernel's).

**Unblocks.** Proved meaning true, which V1 to V3, T4d's obligations, the check door's output path, T6a1b's `by` and
T5g's stamps all rest on.

**Migration**, each step building itself:
1. The closure rule, its outcome lines, and R2's first step with it: both judges printed are the only alarm for this
   class. It lowers a ratchet, so it is a T step under §14 with its measures, or the user's call; it is not a small
   fix of the standing OK.
2. Rows checked against their meaning's type.
3. t5b-effects lands; the refusal names the effect.
4. Only then the check door's output path, V3's facts and the stamps' import.

**Risk:** low as code, one line; the measure decides how many definitions and Proved lines it costs.

### R2. One law, one elaboration, two judges

**Now.**
- **Three readings, two compiles:** a build erases a law (extensions/laws.wap); verify.wasm makes it the bool
  function of its binders (extensions/law_statements.wap) and reads the types module from its sources
  (extensions/verify/laws.wap:44-71); the compiler's `laws` command makes it a function trying the statement on
  trial values (extensions/law_runs.wap, through verify_rules.wap), from the warm state. Two processes, joined by the
  law's name (driver.wap:97-139): one statement typed twice, in two library states.
- **One word for two judges:** the run's FAILED replaces the kernel's Proved (driver.wap:139). `law grows(x: int):
  x + 1 > x`, Proved by the kernel's exact int and FAILED at `x = 9223372036854775807` by the wrapping run, prints
  `FAILED` like any false law; 10.2's alarm has no verdict of its own.
- **All or nothing:** the laws are one module, so one law that does not compile leaves every law unrun, one that
  raises leaves every law without a run verdict, and one that never ends stops `wap verify` (R1's `spin`).
- **Proved laws never run:** the run leaves out a law with a proof and one whose binders are unwritten
  (law_runs.wap:3-4); coc-plan.md:823, "Every proved law is still run on test values against the compiled program",
  holds for no law with a `by`.

**Target.** `wap verify` compiles the program once, each law the bool function of its binders (law_statements.wap's
rule, for laws with a proof too: the proof is the kernel's, the statement the run's). The kernel judges that
declaration; the same module exports each law's function, and lib/laws.wap's trial values feed it law by law, each
call with its own trap and time cap, a trap or a timeout that law's FAILED. A verdict names both judges: Proved,
Tested, FAILED with its counterexample, Untested, and a Proved law that fails when it runs as its own verdict,
exiting non-zero and naming 10.2's believed translation.

**Deletes and adds.** law_runs.wap (18) and law_statements.wap (11) become one rule file of about 10; driver.wap's
join (laws_checked's two compiles, verdicts_joined, verdict_beside: about 45) about 20; verify emits the laws'
module (about 15, compiler.wap's emitting half shared, as "A proved obligation loses its run check" plans it); the
runner per law about 10. Net about −30, no core.

**Unblocks.** V1 on one elaboration; 10.2's run of proved laws; T8's wrapping shown as a disagreement; every law that
runs a test of R1.

**Migration**, each step building itself:
1. The join prints both judges (driver.wap, about +3), with R1's first step.
2. Each law run alone, its trap and its time its own.
3. One compile in verify, the laws' module emitted from it; the `laws` command and law_runs.wap go.

**Risk:** low, extensions only.

### R3. Conversions are declared functions

**Now.**
- **One function of ordered special cases:** conversion(given, wanted, s) (core/analyze/fits.wap:104-136) decides
  every fit in about 30 arms over ten kinds (enum Conversion, fits.wap:96). Three name the domain: `int` to `float`
  (fits.wap:125) by the opcode f64.convert_i64_s (fits.wap:99), a bool counted as an int by i64.extend_i32_u
  (fits.wap:102-103, calls.wap:224), atoms read as Node (Read). Each landing that gave a new way to fit added an arm:
  a subtype's parent (Subtyped), union parts, failable values, a class's extensions, bool counting.
- **The plan says otherwise, three times:** §4's row "char to text, range to list, case to enum, int to float:
  conversions inside the typing code | conversions declared in the types module"; 5.4; §8, "coercions as declared
  functions"; and the T4 row's "declared conversions". No step builds them: T4a and T4b landed without them, and
  coc-t3.md:160's "its conversions leave with T4" did not happen.
- **The kernel reads no body with a conversion:** terms.wap:76 ("a body converted to the result, an int given where
  an int? is, is no term yet"), :105 ("each argument of its parameter's own type"), row_term only the integer rows
  (:115). `half(n: int) as float := n / 2.0` and `maybe(n: int) as int? := n` stay assumed, and their laws are
  refused (appendix 1).

**Target.** A conversion is a function the types module declares as one (`float(n: int)`, its body the prim; a
subtype's parent; and, once they are declared types, a sum's constructors: a case to its enum, a part to its union,
`T` to `T?`). The elaborator's one mechanism finds the declared conversion from the given type to the wanted one,
refuses two paths (§8), lifts it through a list, an optional value and a map's values, and writes the call. What it
writes is an ordinary call: the kernel reads it as one and the emitter emits it as one, and a new conversion (T4c's
char, T8c's storage, Q1's `quotient.of`, C2's trait values) is a declaration, never an arm. Conversion keeps only
the kinds that write no code (Same, Settled, Adapted).

**Deletes and adds.** core about −40 (the domain arms, WIDENING and COUNTING with their call sites, repacked's arms)
and about +15 (the lookup and its uniqueness); types about +30. Boxed, Wrapped, Narrowed and Checked stay until the
sums are declared types.

**Unblocks.** T4c; T8c, which counts "about core +10 in fits.wap's conversions" (coc-plan.md:1654); Q1; C2's trait
values; bodies with a widening or an optional result defined in the kernel; 5.4's "core knows no library word" for
numbers.

**Migration**, each step building itself:
1. The declared-conversion arm beside the others, `int` to `float` moved first (WIDENING goes).
2. bool counting.
3. A subtype's parent.
4. The sums' constructors, with their declarations.

**Risk:** medium: fits is typing's hottest path, and the search for a path must stay unique.

### R4. Identity by number from bind on

**Now.**
- **A definition is a text:** the definer id `"f#n"` (core/stage.wap:199-203) inside a place key `"f#n name sig"`
  whose signature part type_text rebuilds on each call (stage.wap:206, 213); a Signature holds `name` and `key`
  (core/bindings.wap:72).
- **About 128 lines after bind find a definition, a record or a type by its spelling:** calls.wap:69, 110, 172,
  190-196, 231, 266, 297; shapes.wap:43; record_named (stage.wap:306-314, "else the one declared last", 29
  callers); verify keys laws by their written name (extensions/verify/laws.wap:55-56); the provers find laws by name
  (extensions/prove/goals.wap:41-52, 101; rewriting.wap:77, 174).
- **The kernel keeps a log by number and reaches it by text** (kernel/environment.wap:159-173, 210, 298-308): a
  Declaration has no number and `declared` gives none back, so the one just given is found again by name
  (kernel/typing.wap:190). The environment is changed in place and taken back by marks (environment.wap:312-358,
  about 60 lines with their bookkeeping), where T2's row says "keeps declarations by id and is persistent".
- **One namespace for a program and the core's declarations:** the `·` mark keeps a program from meeting count,
  logic and the products (kernel/counting.wap:17-40, logic.wap:13-20); the unmarked ones collide: `law
  equal_symmetric(a: int, b: int): a + b == b + a` is refused, "equal_symmetric is declared already", where the same
  law named `fine` is Proved (appendix 1). The `·Pair` fix (6e8326ba) is this class.
- **Facts by text:** 49 fact names, each fact a Key in a list that every read scans comparing texts
  (stage.wap:95-106, about 250 call sites). In the self-compile, fact_of takes 6.9% of the time, text equality 6.0%,
  meta_unwrapped 3.3%, the name tables' hash 2.0% and fact_name 0.9%: up to a fifth, not all of it identity
  (appendix 2).

**Target.** Bind gives each definition a number; a Signature, a place key, a kernel Declaration and every fact that
points at a definition carry it. A written name goes from its spelling to its candidates once, at bind or at the one
place typing decides it (`x.f`, a case of the enum wanted), and is never looked up again. The kernel's `declared`
gives the new environment and the declaration's number, or a refusal, so nothing is taken back, and the core's own
declarations are a record of their own, as the kernel's `e.products` is, which no program's name can meet. A fact's
name is an enum's case, its slot found by number.

**Deletes and adds.** About 450 to 550 lines touched, most of them the types of keys (57 text-keyed tables in
analyze and emit, Signature, Placed, TypedLaw). Deleted: the marks and take-backs (about 60 kernel lines, holes.wap's
26), the `·` spellings, place_key's text rebuild. Added: the number in Signature and Declaration (about 30), the
record of the core's declarations (about 20).

**Unblocks.** The name clashes as a class; a `by`'s laws found by their declaration (5cd65e54's open lookup); T5g,
whose declarations keep their identity across modules; a share of the time names and facts take.

**Migration**, three parts at three times:
1. **Now, a speed card:** fact names as an enum's cases, the call sites unchanged (stage.wap, about 65 lines),
   measured.
2. **With T5g, a kernel cleanup:** a Declaration carries its number, `declared` gives it back, the core's
   declarations a record apart; the `·` marks and the `equal_symmetric` clash go.
3. **After the open T branches land:** definer numbers through analyze, place keys a pair, the environment
   persistent and its marks gone.

**Risk:** medium to high for part 3: it is wide and collides with every open branch (t5b-effects alone is 28
commits); parts 1 and 2 are local.
